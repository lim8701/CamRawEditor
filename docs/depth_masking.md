# 거리 범위 마스킹 (Depth Range Masking)

라이트룸 "Depth Range Mask" 식 **거리 기반 로컬 조정**. 단안 깊이 추정(ONNX)으로 사진의 상대
거리 맵을 만들고, near~far 범위에 드는 영역만 마스크로 쓴다. 프리뷰(GPU 셰이더)와 Export(numpy)가
**기존 마스크 경로를 그대로 공유**하므로 셰이더·pipeline 은 변경되지 않는다.

관련 파일: `depth.py`(엔진) · `main.py`(캐시/워커) · `ui/Main.qml`(Depth 탭) ·
`models/README.md`(모델·실측·라이선스).

---

## 1. 왜 필요한가

기존 마스크 소스는 **"무엇인가"** 만 가른다 — Scene(SegFormer-B2 / ADE20K 7종), Face(19클래스).
그래서 거리로만 갈리는 영역은 선택할 방법이 없었다:

- 같은 초목인데 **앞쪽 잎만** 어둡게
- **인물 뒤 배경 전체** (배경에 하늘·건물·초목이 섞여 있어도 한 번에)
- 후퇴하는 벽/길에서 **원거리 구간만**

`CLAUDE.md` 의 `향후 후보` 에 있던 "범위 마스크"의 거리 축 구현이다.

## 2. 전체 파이프라인

```
프록시 QImage(헤드룸 카메라네이티브)
  └─(중성 display sRGB 디코드: as-shot WB, 노출0, filmic)────────────┐
                     ↑ Controller._seg_input — Scene/Face 와 동일 입력  │
                       (프록시와 픽셀 정렬 보장)                        ▼
                            display-sRGB RGB(uint8)  ──►  depth.infer_distance()
                                                              │
   ┌──────────────────────────────────────────────────────────┘
   ▼
 [1] 종횡비 유지 리사이즈(짧은 변 518, 14배수=ViT 패치) + bicubic → ImageNet 정규화
     + 뷰 축 삽입([B,1,3,H,W] — V3 는 다중 뷰 모델)
 [2] Depth Anything V3 Small ONNX 추론 → predicted_depth (실제 depth z, 클수록 멂)
 [3] **log z** 로 옮긴 뒤 1~99 퍼센타일 정규화 (반전 없음 → 0=가까움, 1=멂)
 [4] 프록시 해상도 업샘플(cv2 bilinear)
 [5] 휘도 가이드 guided filter(cv2) → 깊이 경계를 실제 엣지에 밀착
   ▼
 거리 맵 float32 [0,1] (프록시 해상도)  ── Controller._depth_map 에 캐시(이미지당 1회)
   │
   ▼  ─── 이하 슬라이더 조작마다 재조합(추론·정제 없음, ~46ms) ─── depth.compose_mask()
 [6] near/far 밴드패스 — 양 끝 feather 폭 smoothstep 진입/이탈
   ▼
 soft alpha 마스크 float32 [0,1]
   │
   └─► **기존 마스크 경로에 그대로 합류**: np.maximum 합집합(Scene/Face 와)
        ├─► SkyMaskProvider(image://skymask, Grayscale8) → 셰이더 binding 9/13~16
        └─► Controller._layer_masks → pipeline.render_full(sky_masks=)
```

**핵심: 셰이더·`pipeline.py`·`coeffs.py` 변경 0.** 마스크는 이미 "프록시 해상도 float32 →
provider / `zoom(order=1)`" 경로가 서 있어서, 새 소스는 알파 배열만 만들어 넣으면 된다.

## 3. 왜 가이디드 필터를 '깊이 맵'에 거는가

`sky_seg` 는 클래스 확률을 합산한 **뒤** 정제한다. 깊이는 순서가 반대다 — 정제 결과가 near/far
와 무관하므로 **미리 한 번** 해두면 슬라이더 드래그에는 smoothstep 비용만 남는다.

| 단계 | 비용(2560×1709 프록시) | 언제 |
|---|---|---|
| 추론 (DirectML) | 0.50s | 이미지당 1회 |
| 업샘플 | 12ms | 이미지당 1회 |
| guided filter (cv2) | 155ms | 이미지당 1회 |
| Otsu 자동 시드 | 3ms | 켤 때 1회 |
| **near/far 밴드패스** | **46ms** | **슬라이더 변경마다** |
| uint8 변환 + `QImage.copy()` | 30ms | 슬라이더 변경마다 |

매 프레임 정제(155ms)는 불가능하고, 미리 해두면 76ms 다. `haze.py` 가 t-맵에 하는 순서와 같다.

## 2-1. 정규화 공간 (모델 선택보다 중요)

모델 출력을 어떤 공간에서 정규화하느냐가 모델 선택보다 결과를 크게 좌우한다.

- **선형 z**: 원거리 꼬리가 길어 근거리가 하위 몇 %로 압축된다(엔트로피 4.55/6).
- **disparity(1/z)**: 원거리가 포화한다 — 산맥 계조가 뭉치고, 산을 고르면 가까운 난간까지
  물든다(V2 가 구조적으로 겪는 문제, 최악 3.98/6).
- **log z (채택)**: 양쪽을 피한다. 최악 케이스 4.78/6 로 가장 안정적이고, 사람의 깊이 지각·
  피사계심도가 대략 log 스케일인 것과도 맞는다.

⚠️ 첫 구현은 V2(disparity 출력)를 골랐는데, **비교 자체가 틀렸다** — V2 와 V3 에 똑같이 선형
정규화를 걸어서 V3 의 근거리 압축을 모델 결함으로 오판했다. 물리량이 다르면 같은 정규화를 쓸 수
없다. 전체 실측표와 되돌리는 방법은 `models/README.md` 참조(재조사 금지).

## 3-1. 왜 디바운스가 아니라 스로틀인가

체크박스용 `maskApplyTimer`(220ms 디바운스)를 그대로 쓰면 **체감 지연의 74%가 대기 시간**이 된다
(측정: 220 + 46 + 30 + 프레임 ≈ 310ms). 더 근본적으로 디바운스는 "움직임이 멈춘 뒤" 발화하므로
연속 슬라이더에는 구조적으로 안 맞는다 — 드래그 중엔 아무 것도 안 보이고 손을 놓아야 갱신된다.

깊이 전용 경로만 **스로틀**로 바꿨다(`win._throttleMask`): 즉시 한 번 보내고, 이후에는
**워커가 끝나는 대로 가장 최신 값만** 보낸다. 갱신 주기가 추측한 상수가 아니라 실제 비용에
스스로 맞춰지고, 드래그 중에도 계속 갱신되며 스레드가 쌓이지 않는다(`controller.skyBusy` 게이트).

⚠️ 트레일링 타이머는 이미 돌고 있으면 `restart()` 하지 않는다 — 그러면 드래그가 이어지는 동안
계속 밀려 디바운스로 되돌아간다.

`_commitMaskKeys(a, throttle)` 의 두 번째 인자로 갈린다. 체크박스는 여전히 디바운스(연타
코얼레싱이 목적), 깊이 슬라이더만 스로틀이다.

### 3-2. Scene∪Face 성분 캐시 (필수 — 없으면 드래그마다 dim)

마스크는 **합집합**이라, 캐시가 없으면 깊이 범위만 바꿔도 `_mask_worker` 가 Scene 성분을 통째로
다시 만든다. `sky_seg.compose_mask` 는 프록시(2560×1709)에서 **896ms** 다:

| 단계 | 비용 |
|---|---|
| 업샘플 + smoothstep | 166ms |
| **scipy guided filter** (r=20) | **566ms** |
| `binary_fill_holes` | 154ms |

실측(DSCF1839, Depth+Scene(sky)): 드래그 사이클 **947~1003ms** → 매 사이클 dim(350ms 문턱).
그 레이어에 Scene 클래스가 켜져 있느냐에 따라 갈리고 Scene 선택은 레이어별로 사이드카에
저장되므로, 증상이 **"어떤 사진에서만"** 나타난다. Face 는 크롭 단위라 영향이 없다(~70ms).

→ `Controller._layer_segmask` / `_layer_segkeys` 에 **레이어별 Scene∪Face 성분**(깊이 합집합
**전** 상태)을 캐시하고, 비-깊이 key 가 그대로면 재사용한다. **947ms → 74ms.**
검증: 캐시 有/無 결과가 비트 동일(max|diff| 0.000e+00), key 추가 시 무효화, 이미지 전환 시 무효화.

⚠️`np.maximum` 은 새 배열을 반환하므로 캐시 배열이 깊이 합집합으로 오염되지 않는다. 캐시 쓰기에는
`img_gen` 가드가 필요하다(`_seg_probs` 와 같은 레이스 — 합성 중 이미지가 바뀌면 이전 이미지 성분을
되살린다).

### 3-3. 공유 경로 최적화 (Scene 토글까지 함께 빨라짐)

위 캐시는 깊이 드래그만 구제한다 — Scene 체크박스 토글 자체는 여전히 896ms 였다. 두 가지를 같이
고쳤고, 둘 다 `sky_seg`/`main` 의 **공유 경로**라 Scene·Face·Depth 가 함께 빨라진다:

1. **`sky_seg._guided_filter` → cv2.boxFilter** (610ms → 165ms, 3.7×). 하늘 마스크·디헤이즈
   t-맵·휘도 NR(프리뷰 + **export pipeline**)이 모두 이 함수를 쓴다. 프리뷰와 export 가 같은
   함수를 쓰므로 정합은 자동으로 유지된다.
   ⚠️**비트 동일은 아니다** — running-sum 누산 순서 차이로 float32 오차가 남는다(실사용 반경
   r≥4 에서 max|diff| 1.2e-07, r=1 에서 1.9e-06). 소비측 양자화(Grayscale8 = 3.9e-03,
   nrBase 16bit = 1.5e-05)보다 훨씬 작아 표현 가능한 정밀도 아래다.
   부수 정리: `face_seg._guided`(cv2 사본)는 존재 이유가 없어져 `sky_seg._guided_filter` 로
   위임하는 별칭이 됐다.
2. **`srgb_to_linear` → LUT 조회** (273ms → 76ms, 3.6×, **오차 정확히 0**). 프록시는 8bit 라
   입력이 256가지뿐이고 `raw_loader._srgb2lin_lut()` 이 이미 있다. `u8*257/65535 == u8/255` 가
   정확히 성립(257×255 = 65535)하므로 근사가 아니다. `_native_to_scenelinear(arr, u8=…)` 에
   경로를 추가하고, 이걸 쓰는 네 곳(세그 입력·haze·휘도 NR·AI NR 워커)을 전부 전환했다.

결과(프록시 2560×1709, 중위값): `sky_seg.compose_mask` **896 → 489ms**,
`_sky_input_rgb` **964 → 740ms**(최종 uint8 출력은 max|diff| 0 — 완전 동일).

Scene 토글은 여전히 350ms 문턱을 넘어 dim 이 뜬다. 남은 비용은 `compose_mask` 쪽
`binary_fill_holes` 154ms + 업샘플/smoothstep 166ms, `_sky_input_rgb` 쪽 `filmic` 283ms +
clip/uint8 변환 346ms 다. 완전히 없애려면 그 단계들까지 손대야 한다 — 별건.

### ⚠️ 밴드패스를 셰이더로 옮기지 않는 이유 (재조사 방지)

거리 맵을 텍스처로 보내고 범위를 uniform 으로 넘기면 슬라이더가 Exposure 처럼 **1프레임(~16ms)**
반응이 된다 — CPU 작업·워커·provider 재로드가 전부 사라진다. 설계·비용까지 검토한 뒤
**스로틀(~100ms 연속 갱신)로 충분하다고 판단해 채택하지 않았다.** 다시 꺼내려면 아래가 필요하다:

- binding 17 에 거리 맵 텍스처(프록시 해상도 단채널, `hazeT`=binding 11 과 같은 패턴).
  레이어 5개가 **텍스처 하나를 공유**한다 — 거리 맵은 레이어별이 아니라 이미지별이다.
- `skyD0..skyD4` = vec4 5개(near, far, feather, hasDepth). std140 여유는 충분하다.
- 마스크 합성이 셰이더로 이동: 텍스처는 Scene∪Face 만 담고 셰이더가 `max(segM, band)`.
  **invert 를 합성 뒤에** 적용해야 한다(현재는 텍스처 값에 바로 `mix`).
- `pipeline.py` 미러: `render_full` 이 거리 맵 + 레이어별 범위를 받는다(`haze=` 방식). 정합
  자체는 깔끔하다 — 양쪽 다 "bilinear 업샘플 → smoothstep" 순서라 결과가 맞는다.
- 가장 까다로운 자리: "이 레이어에 마스크가 있나" 판정. 지금은 `_layer_masks[i] is not None` 으로
  `hasSkyMask`·`layerHasMask`·`maskSettled`·배치 export 게이트가 판단하는데, depth 전용 레이어는
  seg 마스크가 없어도 마스크가 있는 셈이 된다.
- ⚠️거리 맵을 **Grayscale8 로 올리면 안 된다**(256단). Feather 0.005 구간이 ~1.3단에 걸려 계단이
  보인다 → Grayscale16 필요(`nrBase` 가 RGBA64 로 16bit 업로드하는 전례 있음).

즉 얻는 건 ~100ms → ~16ms 이고, 잃는 건 "셰이더·pipeline 무변경"(= 프리뷰=Export 정합 표면이
한 군데 늘어남)이다. 사용자 판단: **속도가 나쁘지 않아 현행 유지.**

cv2 를 쓰는 이유: scipy `uniform_filter` 는 같은 연산이 612ms, cv2 `boxFilter` 는 155ms
(**4.0×**, 수치 동일 max|diff| 1.2e-7). `face_seg._guided`/`_resize` 를 재사용해 3번째 복사를
만들지 않았다(얼굴과 무관한 순수 cv2 유틸).

## 4. 상태 저장 — keys 에 얹기

깊이 범위는 레이어의 `keys` 목록에 **`depth@near,far,feather` 한 항목**으로 들어간다.
얼굴 선택이 `face@0.412,0.318`(정규화 중심좌표)로 저장되는 것과 같은 방식이다.

이렇게 두면:

- **사이드카 저장·undo·재오픈 복원이 자동** — `skyEditParams`/`applySkyEdits` 가 keys 를 이미
  직렬화하므로 새 필드가 필요 없다
- `_mask_worker` 의 `np.maximum` 합집합·staleness 폐기·`_set_layer_mask` 가 전부 무변경
- 새 Python 슬롯도 불필요 — QML 이 keys 를 만들어 기존 `setMaskClasses` 로 보낸다

⚠️ **소수 4자리 고정.** QML `toFixed(4)` == `depth.range_key` 여야 `setMaskClasses` 의
no-op(같은 값 재요청 차단)이 동작한다. 포맷이 어긋나면 슬라이더를 놓을 때마다 같은 마스크를
다시 만든다.

QML 쪽 `depthOn`/`depthNear`/`depthFar`/`depthFeather` 는 **슬라이더 표시용 미러**다.
진실원은 keys 이고, `_syncDepthFromKeys()`(keys→미러) / `_commitDepth()`(미러→keys)가 잇는다.

## 4-1. 초기 범위는 이미지 분포에서 시드한다

고정 기본값은 **원리적으로 맞을 수 없다.** 퍼센타일 정규화를 거쳐도 거리 분포가 장면마다 크게
다르다 — 실측 6장의 평균이 0.478~0.679 로 흩어진다. 초기 Far=0.45 가 "기준이 애매하다"고
느껴진 이유이고, 게다가 그 값은 *전경*을 골라서 가장 흔한 의도(*배경만 손보기*)와 반대였다.

그래서 **켜는 순간 이미지 자신의 히스토그램에서 시드**한다(`depth.auto_range`): 1-D Otsu로
근/원 두 덩어리를 가르고 먼 덩어리를 고른다(near=경계, far=1).

닭-달걀 문제가 있다 — 켤 때는 아직 거리 맵이 없다(추론은 첫 사용 시 lazy). 그래서:

```
체크박스 ON → keys 에 `depth@auto` 센티넬 커밋
           → 워커가 거리 맵 생성 → auto_range 로 확정 → 마스크 생성
           → _depthAutoSig → Controller._on_depth_auto:
                _layer_keys[layer] 의 센티넬을 실제 값 키로 교체
                depthAutoResolved(layer, near, far, feather) 발화
           → QML: 센티넬 교체 + 미러/슬라이더 반영 (_loadingLayer 로 재조합 억제)
```

⚠️ **컨트롤러와 QML 의 키가 완전히 같아야 한다**(정렬 포함). 한쪽만 바꾸면 저장된 키가 여전히
`auto` 라서 같은 값으로 다시 오는 `setMaskClasses` 가 no-op 으로 걸러지지 않고 워커를 한 번 더 돈다.

실측(6장): 자동 경계 0.521~0.604, 커버리지 0.277~0.667 — 전부 "배경"으로 안착했다.
히스토그램은 **stride 4 표본**으로 센다 — 전체(4.4Mpx)는 40.7ms 인데 274k 표본은 3.4ms 이고
**경계가 6장 모두 완전히 동일**했다(diff 0.00000). 평면적/상수 장면에서 Otsu 가 끝으로 치우치면
기본값이 '전부/전무'가 되므로 `AUTO_MIN/MAX = 0.15/0.85` 로 클램프한다.

`_commitDepthAuto()` 는 `depthOn` 을 **스스로** 세운다 — 호출자(체크박스)가 먼저 세우는 것에
의존하면 다른 경로에서 센티넬만 들어가고 UI 는 꺼진 상태로 남는다(실제로 났던 버그).

**늦은 시드 레이스 — 이중 가드가 필수다.** 첫 사용 추론은 0.7~6s 걸리는데, 그 사이 사용자가
슬라이더를 움직이거나 Clear 를 누를 수 있다. 뒤늦게 도착한 시드가 그걸 덮으면 "방금 조작한
슬라이더가 시드값으로 튕겨 돌아가는" 버그가 된다. `img_gen` 가드로는 못 막는다(같은 이미지).

- **Controller `_on_depth_auto`**: `_layer_keys[layer]` 에 `depth@auto` 센티넬이 **아직
  그대로일 때만** 적용. (수동 커밋이 이미 도달했다면 폐기)
- **QML `onDepthAutoResolved`**: QML 쪽 keys 에도 센티넬이 있을 때만 적용. 추론 중에는
  `skyBusy` 라 수동 커밋이 트레일링 타이머에 걸려 **컨트롤러에 아직 안 갔을 수** 있다 —
  컨트롤러 가드만으로는 그 틈의 시드가 QML 슬라이더를 덮고, 이후 트레일링 커밋이 덮인 값을
  보내 수동값이 통째로 사라진다. (그 반대 — 컨트롤러=시드/QML=수동으로 갈라진 상태는
  트레일링 커밋이 수동값을 보내면서 자연 수렴한다. 검증됨)

**드래그 게이트**: `depthNear/Far/Feather` 슬라이더는 `editDragActive` 열거에 포함돼야 한다
(그 열거는 "모든 드래그 소스 명시" 규칙이다). 빠지면 드래그 중 undo 스텝이 쪼개지고 사이드카가
중간 저장되며, AI 디노이즈 타일 루프가 조작 중에 일시정지되지 않는다.

## 5. 후처리 계수 (하늘/얼굴과 다르게 튜닝)

| 계수 | 값 | 하늘 | 이유 |
|---|---|---|---|
| `GUIDED_RADIUS_FRAC` | 0.012 | 0.012 | 동일(짧은 변 비율 — 해상도 독립) |
| `GUIDED_EPS` | **1e-3** | 1e-4 | 깊이는 매끄러운 신호 — eps 가 작으면 텍스처가 배어든다 |
| 구멍 채우기 | **안 함** | 함 | 깊이 밴드는 구멍이 정상(원거리 밴드 속 가까운 나뭇가지) |
| `PCT_LO/HI` | 1 / 99 | — | 출력 스케일이 임의라 절대값을 못 쓴다. 이상치를 잘라 슬라이더 범위 안정화 |
| `AUTO_MIN/MAX` | 0.15 / 0.85 | — | 자동 시드 클램프 — 평면 장면에서 Otsu 가 끝으로 치우쳐도 '전부/전무'를 피한다 |
| `DEFAULT_FEATHER` | 0.10 | — | 자동 시드가 쓰는 feather(경계 폭은 장면 의존이 약해 고정) |

## 6. UI (Masking 패널 → Depth 탭)

Scene / Face 에 이어 세 번째 탭. 클래스 체크박스 그리드 대신 전용 블록이 뜬다:

- **Use distance range** 체크박스 — 범위 자체가 선택이므로 명시적 on/off 가 필요하다
  (0..1 전체는 "전부 선택"이라 의미가 없다). 켜면 이미지 분포에서 자동 시드(§4-1).
- **Near / Far / Feather** 슬라이더 — `SkySlider` 재사용(더블클릭 리셋 규칙 포함).
  더블클릭 리셋 기본값은 배경 방향(Near 0.5 / Far 1.0)이다 — 자동 시드가 실패해도 방향은 맞게.
- 탭 라벨의 `● 1` 은 범위가 켜져 있음을 뜻한다(클래스 개수와 성격이 달라 `maskTabCount(2)` 는
  별도 분기)

**`SkySlider.keepOverlay`**: 조정 슬라이더는 드래그 중 빨간 오버레이를 끈다(보정 결과를 봐야
하므로). Depth 범위 슬라이더는 반대로 **무엇이 선택되는지**가 목적이라 오버레이를 켜둔 채
움직여야 한다 → 이 옵션을 켠다. (라이트룸의 "Visualize Depth" 와 같은 역할을 기존 오버레이가
대신하므로 별도 depth visualizer 는 만들지 않았다)

## 6-1. 다른 상태 경로와의 상호작용 (검증됨)

깊이 범위를 keys 에 얹은 덕에 아래가 **추가 코드 없이** 동작한다. 회귀가 걱정되면 이 목록으로
재확인한다(헤드리스로 전부 검증 가능):

| 경로 | 동작 | 확인 포인트 |
|---|---|---|
| **배치 export 게이트** | 깊이 단독 레이어에서도 `maskSettled`·`hasSkyMask` 가 참이 된다 | 장당 20초 타임아웃을 기다리지 않는지 |
| **사이드카 저장** | `depth@auto` 센티넬이 아니라 **확정된 실제 값**이 저장된다 | 저장된 keys 에 `auto` 가 없어야 한다 |
| **copy/paste edits** | 붙여넣은 near/far 가 **그대로 쓰인다**(자동 시드로 덮이지 않음) | `applySkyEdits` 는 저장값을 복원하므로 시드가 개입하지 않음 |
| **레이어 삭제 시프트** | `depth@` 키가 앞 슬롯으로 따라가고 마스크·UI 미러가 함께 갱신된다 | 시프트 후 `depthOn`/`depthNear` 가 맞는지 |
| **세그 캐시 오염** | 시프트로 슬롯 내용이 바뀌어도 이전 Scene 성분이 남지 않는다 | 캐시를 전부 비우고 재계산한 결과와 비트 동일 |

⚠️**테스트 작성 시 함정**: `skyBusy` 만 기다리면 스로틀 트레일링 타이머(60ms)가 아직 발화하지
않은 순간을 '완료'로 오인한다. 마스크가 가라앉기를 기다릴 때는 이벤트 루프를 충분히 돌린 뒤
`skyBusy`·`_sky_pending` 을 다시 확인해야 한다(실제로 이 때문에 정상 코드를 버그로 오진했다).

## 7. 알려진 한계

- **거리는 이미지별 상대값이다.** near/far 가 사진 간에 그대로 옮겨가지 않는다 —
  copy/paste-edits 로 붙이면 다른 영역이 잡힐 수 있다(UI 문구로 고지).
- 유리·수면·거울은 깊이가 물리적으로 모호해 장면 의존적이다.
- 위에서 내려찍은 평면적 장면은 깊이 분산이 작아 분리력이 약하다 — Scene/Face 가 맞는 도구.
- 마스크 경계 정밀도는 **프록시 해상도가 상한**이다(Scene/Face 와 동일한 구조적 제약 —
  프리뷰=Export 정합을 위해 프록시 마스크를 양쪽이 공유한다).

## 8. 후속 후보 (미구현)

같은 거리 맵을 재사용하는 확장. 사용자 평가 후 순서 결정.

1. **교집합/게이트 모드** — "하늘 중 원거리만". 지금은 합집합만 있어서 거리로 세그를 좁힐 수
   없다. UI 에 합성 모드 개념이 새로 생긴다.
2. **대기 원근 헤이즈** — 디헤이즈 `−` 방향(현재 흰 베일 톤 모델)을 거리 비례 물리 모델로 승격.
   `haze.py` 의 DCP 가 야경에서 `conf→0` 으로 폴백하던 약점이 깊이에는 없다.
3. **초점면 샤프닝 / 거리 변조 그레인·비네팅** — 배경까지 바스락거리는 디지털 느낌 제거.
4. **거리 스플릿 토닝** — 전경 웜 / 원경 쿨.
5. **렌즈 블러(피사계심도)** — 효용은 크나 깊이 경계 헤일로가 NAFNet 디블러가 기각된
   "인위적/지우개" 느낌을 재현할 위험. 하려면 "약한 초점 이탈"로 스코프를 좁힌다.
