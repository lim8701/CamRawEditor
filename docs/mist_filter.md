# 미스트(디퓨전) 필터 — 산란 모델

렌즈 앞 미세 입자가 빛의 일부를 산란시키는 광학을 scene-linear 에서 재현한다. 하이라이트
주변의 부드러운 후광, 화이트 미스트의 화면 전체 베일이 여기서 나온다.

관련 파일: `mist.py`(모델) · `coeffs.py`(`MIST_*`) · `pipeline.py`(1단계) · `shaders/adjust.frag`(1단계)
· `main.py`(`MistProvider`/`_mist_worker`) · `ui/Main.qml`(MIST 섹션)

> ⚠️ **이 모델은 미측정이다.** 커널 모양은 글레어 산란 문헌의 형상(1/θ² 꼬리)을 prior 로 쓴
> 것이고, 실제 필터를 재서 피팅한 값이 **아니다** — 그레인(필름 스캔 4롤 피팅)이나 디헤이즈
> (DCP 물리)와 지위가 다르다. 아래 [실측으로 가는 길](#실측으로-가는-길) 을 위해 계수를 전부
> `coeffs.MIST_*` 로 빼 뒀다. 실측 A/B 페어가 확보되면 그 값만 교체하면 된다.

---

## 모델

```
out = (1−k)·L  +  k·(P ⊗ (L·E))
```

| 기호 | 뜻 |
|------|-----|
| `L` | **카메라네이티브 scene-linear** (헤드룸 디코드 직후 — 유저 WB·매트릭스·노출 전) |
| `k` | 산란 비율 = `Amount × MIST_K` |
| `P` | 정규화된 산란 커널(∫P=1) — 가우시안 3개 + 균일항 |
| `E` | 하이라이트 보상 (클리핑으로 잃은 초과 에너지 근사) |

**filmic 앞이어야 하는 이유.** 산란은 렌즈에서 일어난다. 톤커브 뒤에 넣으면 하이라이트가 이미
1.0 으로 압축된 뒤라 후광이 물리적으로 어긋나고, 밝기 순서가 뒤집힌 회색빛이 된다. 그 안에서
**정확히 어디인지**는 아래 [파이프라인 위치](#파이프라인-위치) 에서 따로 정한다.

**균일 회색이 안 변하는 것으로 정규화를 검증한다** — 커널이 정규화돼 있으면 평탄한 입력은
그대로 나와야 한다(실측 최대 편차 1.6e-05, char 0/0.5/1 전부).

## 왜 단일 가우시안이면 안 되는가

실제 디퓨전 필터의 산란 프로파일은 **좁은 코어 + 아주 넓고 옅은 스커트**의 합이다. 단일
가우시안은 두 갈래로만 실패한다 — σ 를 좁게 잡으면 소프트포커스(해상력만 손실), 넓게 잡으면
아무 변화가 안 보인다. σ 를 **기하 간격(비 4)** 으로 세 개 두고 무게를 나누면 그 구간에서
멱함수 꼬리를 근사한다.

점광원(1024px 프레임 중앙 1픽셀) 반경 프로파일에서 확인한 꼬리 기울기:

| 무게 세트 | r 5→30px 감쇠 | 유효 기울기 |
|-----------|--------------|------------|
| 화이트 | 0.0222× | **r^-2.1** (설계 목표 1/θ²) |
| 블랙 | 0.0026× | **r^-3.3** (더 급함 = 후광이 하이라이트에 머문다) |
| 단일 가우시안(mid) | 0.0040× | r=75px 부터 **정확히 0** — 스커트가 없다 |

화이트의 인접 반경비는 전 구간에서 0.136~0.170 으로 거의 일정하다(2.4× 반경 스텝에서 1/θ²
가 예측하는 값 0.17). 즉 세 가우시안의 합이 그 구간에서 실제로 멱함수처럼 행동한다.

⚠️ **가장 좁은 성분도 '후광 크기'여야 한다.** 처음 `MIST_SIGMA[0]` 을 0.0010(긴 변 비율)으로
뒀더니 1600px 프레임에서 σ=1.6px, 즉 산란이 아니라 **미세 블러**가 되어 고주파만 깎였다.
선명한 코어는 커널이 아니라 `(1−k)·L` 항이 담당하므로 커널은 **보이는 변위**만 담아야 한다.
0.0025 로 올려 해결.

고주파 유지율이 대략 `(1−k)` 로 떨어지는 것은 **정상이고 물리적으로 맞다** — 산란된 비율만큼
모든 주파수의 대비가 준다. Amount 1.0(k=0.42)에서 실측 50~55%.

## 블랙 vs 화이트 — 별개 알고리즘이 아니다

같은 커널의 **무게 배분** 하나로 갈린다. `Character` 0=블랙 / 1=화이트 가 두 무게 세트를
보간한다.

- **화이트**: 투명 입자만이라 산란광이 다 살아남는다 → 넓은 성분·균일항이 크다 → 화면 전체
  베일, 블랙 상승
- **블랙**: 검은 입자가 넓게 퍼진 산란광을 흡수한다 → 후광이 하이라이트 주변에 머문다 →
  블랙 유지

균일항은 σ→∞, 즉 **프레임 평균**이다(베일링 글레어의 표준 모델). 화이트에만 0.18 이 들어간다.

### 실측 (outEdge 1600, 8bit 코드 단위)

`near`/`far` = 최고휘도점 중심 반경 1~3% / 4~8% 고리에서 **OFF 기준 어두운 절반**의 이득.
`shadow` = OFF 어두운 5% 픽셀의 상승. `hf%` = 고주파 에너지 유지율. `mean%` = 전체 밝기 변화.

| 사진 | 변이 | near | far | shadow | hf% | mean% |
|------|------|-----:|----:|-------:|----:|------:|
| 역광 창문 | 블랙 0.7 | **+25.4** | +8.0 | **+2.6** | 64.1 | +3.2 |
| 역광 창문 | 화이트 0.7 | +34.8 | **+26.9** | **+20.5** | 64.7 | +14.9 |
| 역광 창문 | 블랙 1.0 | +34.0 | +10.9 | +3.6 | 51.9 | +4.3 |
| 역광 창문 | 화이트 1.0 | +46.5 | +35.3 | +26.1 | 52.7 | +19.8 |
| 밝은 간판 | 블랙 0.7 | +7.6 | +7.1 | +2.6 | 62.0 | +4.9 |
| 밝은 간판 | 화이트 0.7 | +6.9 | +14.9 | +27.4 | 61.8 | +17.8 |
| 주광 스트리트 | 블랙 0.7 | 0.0 | 0.0 | +7.2 | 67.5 | +0.9 |
| 주광 스트리트 | 화이트 0.7 | 0.0 | 0.0 | +23.7 | 63.3 | +4.3 |

읽는 법:
- **`shadow` 가 Character 를 가른다** — 같은 Amount 에서 블랙 +2.6 vs 화이트 +20.5, **8배**.
  이 하나로 "블랙은 블랙을 지키고 화이트는 안개가 낀다"가 수치로 성립한다.
- **`near` vs `far` 는 사진에 따라 무력하다** — 확장 광원(간판·창문처럼 큰 밝은 면)에서는
  넓은 성분이 사실상 전역 리프트라 두 고리가 같이 오른다. 그래서 밝은 간판 사진에서 블랙의
  near≈far 다. ⚠️이 지표만 보고 무게를 조정하면 안 된다.
- 주광 사진에서 `near`/`far` 가 정확히 0 인 것은 정상 — 최고휘도점 주변이 이미 filmic 숄더에
  눌려 있어 이득이 표시되지 않는다. 주광에서 블랙 미스트의 변화가 `mean%` +0.9 로 미미한 것도
  실제 필터와 같은 방향이다(후광을 만들 초과 에너지가 없다).

⚠️ 블랙의 wide 무게는 0.10 → **0.05** 로 낮춘 값이다. 0.10 만으로도 확장 광원에서 far 이득이
near 를 넘어(+8.9 vs +8.1) 블랙 미스트의 성질을 잃었다.

## 하이라이트 보상 (E)

현실에서 창문·간판·태양은 미드톤의 수십~수백 배이고, **후광 밝기는 그 초과 에너지에서 나온다.**
그런데 센서에서 클리핑된 픽셀은 기록값이 실제보다 한참 낮다. 그대로 블러하면 후광이 아니라
**회색 뿌연 막**이 된다. `E` 는 클립 근처 픽셀의 잃어버린 에너지를 근사 복원한다.

```
E = 1 + hi · smoothstep(MIST_HL0, MIST_HL1, max(R,G,B))     # 스칼라 → 색 불변
```

- `hi = 0` → 순수 물리 모델(에너지 정확 보존, 실측 평균 변화 1.000×)
- `hi = 0.8`(기본) → 합성 광원 테스트에서 평균 +4.6%
- `hi = 2.0` → +11.4%

⚠️ 이 항 때문에 미스트는 **약간 밝아진다**(실측: 블랙 0.7 에서 +3~5%, 화이트 0.7 에서
+15~18%). 프레임 평균을 강제 보존하도록 정규화하지 **않았다** — 복원된 초과 에너지는 실제로
있었던 빛이고, 화이트 미스트가 화면을 들어올리는 것도 실물의 성질이다. Amount 와 Exposure 의
직교성을 원하면 정규화가 답이지만, 그건 물리를 버리는 쪽이라 기본을 물리에 뒀다.

## 파이프라인 위치

```
   헤드룸 디코드 (카메라네이티브 scene-linear)
1) ★미스트  ← 여기. 유저 WB·cam→sRGB 매트릭스·노출보다 **앞**
0) 유저 WB → 매트릭스 → 노출 → filmic → display sRGB
0.5) 하이라이트 디새추 → 3) 톤영역 → … → 필름시뮬 LUT → … → 12) 그레인
```

**왜 프론트엔드 맨 앞인가.** "산란은 렌즈에서 일어나니 filmic 앞"만으로는 위치가 안 정해진다.
유저 WB·매트릭스·노출은 모두 **픽셀마다 같은 선형 연산**이라 블러와 정확히 교환된다
(`blur∘linear == linear∘blur`). 그 셋보다 앞에 두면 결과는 같으면서 산란 필드가 세 슬라이더와
무관해지고, 그 덕에

- 프리뷰 산란 필드를 **이미지당 1회** 계산해 캐시할 수 있고,
- 균일항(프레임 평균)이 근사가 아니라 **정확**해진다(셰이더에서 프레임 평균을 계산할 방법이
  없어 CPU 가 uniform 으로 넘기는데, 노출 뒤에 두면 노출을 드래그할 때마다 어긋난다).

⚠️E 의 임계만 공간에 의존한다(max 채널을 어느 공간에서 보는지). 그래서 프리뷰와 export 가
**같은 공간에서** E 를 계산해야 하고 `MIST_HL*` 도 그 공간 기준으로 튜닝된 값이다.

- **그레인보다 앞**이어야 한다 — 필터는 렌즈에, 그레인은 유제층에 있다.
- **중성 베이스(`neutral_disp`/`dispSrc`)에는 걸지 않는다** — 텍스처/클래리티/톤영역 마스크가
  쓰는 '장면 구조' 기준이라 미스트가 섞이면 로컬대비 반응이 미스트 값에 따라 흔들린다.
- σ 는 **프레임 긴 변의 비율**이라 프록시(프리뷰)와 풀해상도(export)의 룩이 자동으로 맞는다.
- 넓은 성분은 `1/f` 해상도에서 계산한다(`f = σ/8`). ⚠️축소는 **면적평균 필수** — 점샘플은
  하이라이트를 에일리어싱해 같은 비용에 오차가 2~3배가 된다(date_stamp 글로우에서 실측된 함정).

## 프리뷰 구현 — 커널은 GPU 가 아니라 CPU 가 만든다

3단 구조다.

```
① CPU (main._mist_worker)   프록시 → 산란 필드 3장(축소본, 선형 16bit RGBA64) + 균일항
        ↓                    (Radius, Highlight) 당 1회. QML 이 160ms 디바운스로 요청
② GPU (mistfield.frag)      3장을 Character 무게로 섞어 mistScat 한 장으로 (RGBA16F FBO)
        ↓                    Character 는 uniform → 실시간(프록시 1패스 = 사실상 공짜)
③ GPU (adjust.frag 1단계)   cam = (1−k)·cam + k·mistScat        Amount 도 uniform → 실시간
```

**QML 블러 체인을 못 쓴다.** 산란 소스는 헤드룸(4)×보상(최대 3)=**12 까지 가는 HDR** 이라
[0,1] 텍스처에 그냥 담기지 않고, 감마 공간에서 블러하면 밝은 기여를 과소평가해 후광이 죽는다
(이 기능이 피하려는 실패 모드 그 자체). 그래서 블러는 CPU 가 선형광에서 하고, 그 결과만
아래 코덱으로 담는다.

- 필드는 각기 `_blur_small` 의 자연 해상도(narrow 1/1, mid 1/3, wide 1/12 수준)로 올리고
  **GPU 가 bilinear 업샘플**한다 — 필드가 매끄러워 무해하고 메모리가 100MB → 40MB 로 준다.
- 준비 전에는 `mistOn=0` 으로 미스트가 무동작(NR 베이스와 동형).

### 성능 — Radius/Highlight 재계산 (4.4MP 프록시, 20코어)

| | 이전 | 지금 |
|---|---:|---:|
| radius 0.5 | 2973 ms | **867 ms** |
| radius 1.0 | 1774 ms | **712 ms** |
| radius 2.0 | 2221 ms | **743 ms** |
| 그중 메인 스레드 | 275 ms (UI 프리즈) | **0** |

세 가지로 얻었다.

1. **스트립 병렬**(`_map_strips`) — 행 밴드로 쪼개 스레드로 돌린다. `pad` 를 커널 지지폭
   (scipy 의 `int(4σ+0.5)`) 이상으로 잡으면 결과가 **분할하지 않은 것과 비트 동일**하다
   (실측 0.000e+00, 스레드 수를 1↔8 로 바꿔도 필드·프레임평균 동일). 좁은 성분 827 → 157 ms.
2. **인코딩을 워커로** — 예전엔 `_on_mist_ready`(메인 스레드)에서 해서 275ms 동안 UI 가 얼었다.
3. ⚠️**융합 in-place 로 써야 스레딩이 먹는다.** 임시배열을 만드는 판은 8스레드에서도 190ms
   그대로였고, 같은 계산을 `out=` 로 융합하니 29ms(비트 동일)가 됐다 — malloc 경합이 병렬화를
   먹고 있었다. `scatter_source` 도 같은 이유로 융합했다.

기각한 후보(실측):

| 후보 | 결과 |
|---|---|
| `truncate` 4.0 → 3.0 / 2.0 | 1.2× / 1.8× 인데 오차 0.007 / 0.080 — 룩이 변한다 |
| 좁은 성분도 1/2 해상도에서 계산 | **더 느리다**(1014 ms — 면적평균+zoom 비용) + 오차 0.070 |
| 분리형 1D ×2 로 직접 구현 | 955 ms — scipy 가 이미 내부적으로 분리형이다 |

⚠️디더 시드는 **스트립 시작 행**에서 파생한다(스케줄링 순서와 무관하게 결정적). 스레드 수가
바뀌면 패턴이 달라지지만 진폭이 ±0.5/255 라 무해하고, 같은 기계에서 재로드 시 동일하다
(export 는 코덱을 타지 않으므로 export 와 패턴이 같을 필요도 없다).

남은 큰 선택지는 **필드를 GPU 에서 만드는 것**이다(코덱과 RGBA16F 가 이미 있어 가능해졌다).
그러면 Radius/Highlight 도 즉시 반응하지만, 블러 커널이 scipy 가우시안에서 `blur.frag` 계열의
탭 근사로 바뀌므로 export(numpy)와의 σ 대응을 새로 맞춰야 한다 — 텍스처/클래리티가 이미 그
방식이고 그 σ 환산은 한 번 틀렸던 적이 있다(`_TAP_SIGMA` 주석 참조).

### 저장 코덱 — 로그 인코딩 + 디더 (⚠️여기서 사용자 보고가 두 번 나왔다)

```
저장:   code = log2(1 + v/A) / logK          A = MIST_TEX_LOG_A = 0.01
되돌림: v    = (2^(code·logK) − 1) · A        logK = log2(1 + MIST_TEX_MAX/A) ≈ 10.64
```

필드 텍스처와 합성본 FBO **양쪽 모두** 이 코덱을 쓴다. `mistfield.frag` 는 디코드 → 무게 혼합
(**선형광**) → 재인코드, `adjust.frag` 는 디코드해서 섞는다.

**두 번 실패했다.** 프리뷰 경로에서 16bit 가 유지되지 않는 것이 근본 원인이고, 그때마다 증상이
달랐다.

1. **선형 인코딩** → *"하이라이트 주변 색이 뒤틀린다"*. 8bit 스텝이 0.063(scene-linear)이라
   어두운 영역 참값(~0.02)보다 크고, 채널마다 독립 반올림돼 어두운 면이 **보라색**으로 물들었다.
2. **√ 인코딩** → 색은 잡혔지만 *"층이 진다"*. 상대오차 ~0.8% 는 색을 살렸지만 매끄러운
   준-흑색 면에서 **넓은 등고선(계단판)** 이 남았다.

⚠️**지표를 잘못 잡으면 판단이 뒤집힌다.** 픽셀 오차만 보면 디더는 오차를 *키우므로* 나빠
보인다. 눈에 보이는 것은 **저역통과에서 살아남는 오차**(=결)다. 그래서 지표는

```
coh = gaussian(오차_display코드, σ=4) 의 p99.9      ← 이것이 보이는 양
```

어두운 씬(`dscf8216`, 준-흑색 벽 + 좁은 광원 = 최악 조건) 실측:

| 코덱 (8bit 강하 가정) | coh (display code) |
|---|---:|
| 선형 | 색 뒤틀림(별도 지표: R/B 비 오차 93~602) |
| √, 디더 없음 | **1.303** ← "층" |
| √ + 디더 | 0.271 |
| **log + 디더** | **0.075** |
| (16bit 였다면) | 0.001 |

⚠️**디더는 원해상도 필드에만 걸어야 한다.** 축소된 필드(mid f≈2, wide f≈8)에 걸면 그 노이즈가
업샘플되어 f×f 블롭 — 없애려던 저주파 결이 된다. 실측 coh: narrow-only **0.075** vs all 0.098.
(합성본 FBO 는 원해상도이므로 셰이더에서 디더한다. 채널마다 다른 해시여야 한다 — 하나면
휘도 노이즈만 되고 색 등고선이 남는다.)

⚠️**MIST_TEX_MAX 를 낮춰 정밀도를 벌려 하지 말 것.** DSCF1663 의 필드 최대가 6.81 이라 MAX=4
는 **7.66 코드**를 깎았고(MAX=2 는 47.7) 밝은 내부 후광이 죽는다. 이론 최대(헤드룸 4 × 보상 3
= 12)를 덮어야 하므로 16 을 유지한다.

부수 효과로 **FBO 클리핑 위험도 사라졌다.** 초기 `mistfield.frag` 는 정규화하지 않은 `scat`
(최대 12)을 그대로 출력해서, FBO 가 RGBA8 로 떨어지면 1.0 에서 채널별로 잘려 후광 색이 회전했다.
지금은 출력이 항상 [0,1] 코드다.

⚠️ `format: ShaderEffectSource.RGBA16F` 는 그대로 두었다(있으면 사실상 무손실). 다만 이제
**정확성이 그것에 의존하지 않는다** — Qt/드라이버가 16bit 를 유지하는지에 룩을 걸지 말 것.

### ⚠️ ②를 따로 두는 이유 = D3D11 샘플러 16슬롯

**adjust.frag 에서 필드 3장을 직접 읽으면 앱이 죽는다.** HLSL SM5.0 은 스테이지당 샘플러가
16개(s0..s15)뿐이고 `adjust.frag` 는 이미 16개를 쓰고 있었다. 3장을 더하면 19개가 되어

```
error X4509: maximum sampler register index exceeded, target has 16 slots,
             manual bind to slot s16 failed
→ Failed to build graphics pipeline state
```

**qsb 컴파일은 통과한다** — SPIR-V 단계에는 그런 제약이 없어서 앱을 실제로 띄워 RAW 를
로드해야 드러난다(그렇게 한 번 터졌다). 필드를 미리 한 장으로 섞으면 adjust.frag 는 슬롯
하나로 끝나고 Character 의 실시간성도 잃지 않는다.

그 한 슬롯은 **`stampTex`(binding 6)를 회수**한 것이다. 날짜 스탬프는 `stampOverlay` 가 최종
프레임 기준으로 그리므로 셰이더 경로는 `pipe`/`pipeFull` 둘 다 `stampOn: 0.0` 인 죽은 코드였다.

⚠️ **이제 adjust.frag 는 정확히 16개다 — 새 sampler 를 추가할 자리가 없다.** 필요해지면 단일
채널인 `skyMask0..4` 를 RGBA 채널에 패킹해 3슬롯을 회수하는 것이 먼저다.

### 정합 실측

**`main.py` 가 실제로 만드는 QImage 를 읽어서** 디코드하고(보내는 쪽 + 읽는 쪽을 같이 통과)
셰이더 수식을 재현해 `mist.apply` 와 비교했다 — 필드 인코딩·디더·양자화 → bilinear 업샘플 →
디코드·무게 혼합 → 재인코딩·디더·FBO 양자화 → 디코드까지 **코덱 왕복 2회** 포함.
2장(어두운 실내 / 텅스텐 램프) × 2조합:

| 정밀도 | 어두운 영역 coh (display code) |
|---|---:|
| 16bit (RGBA64 + RGBA16F 유지 시) | **0.022 ~ 0.048** |
| 8bit (다 떨어졌을 때) | **0.079 ~ 0.153** |

8bit 최악값 0.153 도 display 1코드의 1/6 이라 보이지 않는다(문제였던 상태는 1.303 이었다).
⚠️이 검증은 업샘플을 scipy zoom 으로 대신하므로 GPU bilinear 와의 미세 차이는 포함하지
않는다(매끄러운 필드라 무시 가능).

## 손잡이

| 슬라이더 | 범위 | 역할 |
|----------|------|------|
| Amount | 0..1 | 산란 비율 k = `Amount × MIST_K`. 1.0 이 실제 최강 등급(1)보다 조금 위 — 천장이 실물을 넘어야 고를 여지가 생긴다(GRAIN 과 같은 기준) |
| Character | 0..1 | 0=블랙 미스트 / 1=화이트 미스트. 커널 무게 배분 |
| Radius | 0.5..2 | σ 3개 동시 배율 |
| Highlight | 0..2 | 클리핑 보상 E. 0=순수 물리 |
| **Color** | 0..1 | 산란광의 **휘도는 두고 색만** 받는 화면 쪽으로 되돌린다. 0=물리 |

Amount/Character/**Color** 는 uniform 이라 실시간, Radius/Highlight 만 필드 재계산(디바운스)이다.

실제 필터 등급 대응(체감 기준, 미측정): Amount 0.25 ≈ 1/8, 0.40 ≈ 1/4, 0.60 ≈ 1/2.

## Mist Color — 창백함을 되돌리는 룩 노브

**증상 보고:** *"하이라이트 주변이 창백하게 퍼지는 느낌"*(DSCF1662 — 차가운 LED 스트립 +
따뜻한 천장). 조사 결과 **모델은 정상**이었다.

| | sRGB R/G | sRGB B/G | chroma |
|---|---:|---:|---:|
| 광원(LED, 상위 1%) | 0.712 | **1.916** | 0.628 (강한 청색) |
| 후광이 내려앉는 면(천장) | 1.460 | 1.019 | 0.315 (따뜻) |
| **산란광** | 1.143 | 1.097 | 0.125 |
| 대조: 국소 2% 박스평균 | 1.183 | 1.062 | 0.155 |

산란광 ≈ **국소 이웃 평균**(아래 두 줄이 사실상 같다). 차가운 LED 빛이 따뜻한 면에 섞여
회색으로 빠지는 것이고, 그게 베일링 글레어의 정의다. 다른 후보는 모두 배제됐다 —
센서 포화 0.248%·프록시 천장 도달 0.000%(클리핑 아님), `hlDesat` 껐을 때 채도 0.2364 vs
켰을 때 0.2363(무관), `hi=0` 에서도 0.2413(보상 아님).

⚠️**"노출 올린 것과 같다"는 설명은 틀렸다**(한 번 그렇게 답했다). 노출은 **곱셈**이라 채널비를
보존하고, 미스트는 **빛을 더하는** 것이라 반드시 탈색된다 — 같은 밝기로 맞춘 노출 대조군은
채도 −0.019, 미스트는 −0.145(7.6배). 비교 자체가 성립하지 않는다.

그래서 **물리를 기본으로 두고 룩 노브를 하나 더** 뒀다(`mist.tint_scatter`):

```
scat' = mix(scat, L·(luma(scat)/luma(L)), Color · smoothstep(0, MIST_COLOR_FLOOR, luma(L)))
```

휘도는 정확히 보존되고 색비만 받는 픽셀 쪽으로 간다. 실측(amt 0.7):

| Color | 중간톤 채도 | 밝기 증분 |
|---:|---:|---:|
| OFF(미스트 없음) | 0.3252 | — |
| 0.0 (물리) | 0.2872 | +0.0086 |
| 0.5 | 0.3039 | +0.0083 |
| 1.0 | 0.3229 | +0.0079 |

**글로우는 두고 창백함만 뺀다.** 어두운 영역 색 노이즈는 거의 안 늘었다(chroma std 0.2247 →
0.2295, OFF 0.2639) — `MIST_COLOR_FLOOR` 아래에서 물리로 되돌리는 가드 덕분.

⚠️이 항은 **`adjust.frag` 에서** 한다(필드 패스가 아니라). 블러된 필드가 아니라 **원래 픽셀**이
필요하기 때문이고, 그 덕에 uniform 이라 실시간이다. 셰이더 == `mist.tint_scatter` 실측 차이 **0**.

⚠️물리가 아니라 룩 노브다. 근거가 아주 없지는 않다 — 우리 산란은 이미지 공간 블러라 실제
산란이 넘지 않는 깊이·가림 경계를 넘어 색을 섞는다. 그 한계의 거친 보정으로 볼 수 있다.
기본값 0.0 이라 손대지 않으면 물리 모델 그대로다.

## 실측으로 가는 길

계수를 실측으로 교체하려면 아래가 필요하다. **RAW 만**(JPEG 4:2:0 은 이 저진폭 신호를
못 담는다 — 그레인 Color 피팅이 같은 이유로 실패했다), 삼각대 + 완전 수동, 필터 ON/OFF 연속 페어.

1. **점광원 노출 브라케팅** (−6/−3/0/+3 EV) — PSF 를 코어부터 꼬리까지 한 곡선에 담는다.
   브라케팅이 없으면 꼬리를 못 잡고, 꼬리가 이 모델의 전부다. → `MIST_SIGMA`, 무게
2. **광원 + 흑색 패치 동시 프레임** — 떨어진 흑점의 상승이 균일항/화이트 무게. → `MIST_W_*`
3. **필터 등급 스윕**(1/8·1/4·1/2·1) — k 가 등급에 선형인지. → `MIST_K` 스케일
4. **초점거리 2~3개** — 산란은 렌즈 앞에서 각도 θ 로 일어나므로 센서면 변위가 `f·tanθ`,
   즉 σ 가 초점거리에 비례할 개연성이 크다. 사실이면 σ 를 프레임 비율로 고정하면 안 되고
   EXIF 초점거리를 읽어야 한다(`exif_info.py`). ⚠️**가정하지 말고 측정으로 판정할 항목.**
5. **홀드아웃 실사 3~5쌍** — 피팅에 쓰지 않고 채점용으로 남긴다.

⚠️ 과거 헐레이션 측정(4롤)에서 **PSF 가 대칭**이라 비대칭 헐레이션 모델이 기각됐다. 미스트
필터의 산란은 물리적으로 대칭이므로 그 결과와 모순되지 않는다 — 다만 그 건은 **필름 고유
현상의 물리 재현**이라 재시도 금지가 유지되고, 이 건은 **렌즈 액세서리 룩의 재현**으로 별개다.
