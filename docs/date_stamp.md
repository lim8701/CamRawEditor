# 필름 데이트 스탬프 (쿼츠 데이트백) — 물리 과정 재현

## 핵심 사상

이 기능은 날짜 텍스트를 사진 위에 "얹는" 것이 아니라, **실제 필름 카메라의 쿼츠 데이트백이
날짜를 필름에 각인하는 물리적 과정 그 자체를 재현**한다. 데이트백은 필름 뒤편의 작은 LED
어레이가 셔터가 열릴 때 필름 에멀전의 한쪽 구석을 **빛으로 노광**하는 장치다. 즉 날짜는
"사진 위의 스티커"가 아니라 **사진과 똑같은 에멀전에 빛으로 새겨진, 사진의 일부**다.

그래서 구현의 모든 선택은 "이 각인이 실제 필름에서 어떻게 보였을까"에서 출발한다 —
합성 방식, 그레인, 번짐, 색, 위치, 해상도까지.

---

## 실제 물리 과정

1. **광원**: 데이트백의 소형 7-세그먼트(또는 14-세그) LED가 호박색(주황) 빛을 낸다.
2. **노광(가산)**: 셔터가 열리면 그 빛이 필름 에멀전의 한 구석을 이미 맺힌 상(像) **위에 더해**
   노광한다. 빛을 더하는 것이므로,
   - 이미 밝은(과노출된) 하늘/하이라이트 위에서는 더 밝아질 여지가 없어 **흰빛으로 씻겨
     거의 안 보인다**.
   - 어두운 영역 위에서는 주황 각인이 **선명하게** 드러난다.
3. **같은 에멀전**: 날짜도 사진과 동일한 은염 결정에 맺히므로 **같은 필름 그레인**을 탄다
   (디지털처럼 매끈할 수 없다).
4. **할레이션**: 강한 점광원이 에멀전·베이스에서 산란·역반사되어 글자 둘레에 **적색 계열의
   부드러운 번짐(헤일로)** 을 만든다.
5. **프레임 기준 위치**: LED는 **센서(가로) 프레임의 우하단**에 고정 각인한다. 세로로 촬영하면
   (카메라를 회전) 업라이트로 볼 때 각인이 90° 돌아간 채 대응 코너로 이동한다.
6. **현상 후 최종 상(像)**: 각인은 필름에 노광된 뒤 현상되어 나온다 — 즉 크롭/방향이 반영된
   **최종 프레임**에 존재하며, 프레임 크기에 비례한 위치·크기를 갖는다.

|-----------|------|------|
| **LED가 빛을 더해 노광**(가산) | **screen 합성** `out = 1−(1−배경)(1−색×강도)`. 순수 screen 은 하이라이트에서 과하게 사라지므로 source-over 를 소량 섞어(`SCREEN_MIX`) 완화 → 밝은 곳 옅어짐/어두운 곳 선명함은 유지하되 과다 소멸만 억제 | `date_stamp.stamp_export`(export) · `shaders/stamp.frag`(preview) |
| **같은 에멀전의 그레인** | 스탬프 그레인 = **사진 필름 그레인에 연동**(`grainAmt × STAMP_GRAIN_K`). 사진 그레인을 올리면 각인도 같이 거칠어지고, 그레인 0이면 각인도 매끈 | `render_sprite`(grain) ← `grainAmt` |

| **7-세그/14-세그 LED 숫자** | DSEG 세그먼트 디스플레이 폰트(정품 재현) — 7-seg/14-seg Classic 의 Regular/Bold × 정체/이탤릭, 그리고 도트매트릭스(Doto 원형 도트) | `STYLES`(fonts/*.ttf, SIL OFL) |
| **프레임 기준 각인 위치** | EXIF Orientation → 센서 우하단이 업라이트 프레임에서 오는 코너로 스프라이트를 회전·배치(세로 사진은 90° 회전 코너) | `rot_from_orientation` / `corner_for_rot` / `_rotate_sprite` |

## 프리뷰 = Export 정합

각인이 "빛을 더하는" 것이므로 합성은 **배경 픽셀을 읽어야** 한다(어두운/밝은 배경에서 다르게
보이므로). 프리뷰와 export 가 **동일한 screen 수식**을 쓰도록 다음과 같이 맞춘다.

- **Export(numpy)**: `stamp_export` 가 최종 배열 코너에서 배경을 읽어 screen(+source-over 혼합) 합성.
- **Preview(GPU)**: `stampOverlay` 를 **ShaderEffect**(`shaders/stamp.frag`)로 두고, 배경
  (`canvasHolder` = 파이프라인 결과)을 샘플러로 읽어 export 와 같은 수식으로 합성. 스탬프
  스프라이트는 별도 고해상도 텍스처로 유지해 **크리스프**하다.
- 두 경로 모두 `strength(STAMP_STRENGTH)`·`SCREEN_MIX` 등 동일 상수를 사용한다(두 곳 동기).

> ⚠️ **설계 트레이드오프**: 예전에는 셰이더가 스탬프를 직접 합성했으나(정확한 배경-읽기 screen),
> 프록시 해상도라 흐릿하고 크롭 전 좌표라 위치가 어긋났다. 그래서 스탬프를 **최종 프레임
> 오버레이**로 옮겼다. 대신 오버레이가 배경을 못 읽어 한때 source-over(스티커) 로 근사했는데,
> 지금은 오버레이 자체를 **배경을 읽는 ShaderEffect** 로 만들어 "크리스프 + 최종 프레임 위치 +
> 진짜 배경-읽기 screen" 을 모두 달성했다.
>
> ⚠️ **프리뷰 스프라이트 해상도**: 프리뷰 스프라이트는 프록시 기준(`ref_short≈1000`)이라 화면
> 확대 시 다소 소프트하게 보일 수 있다(프록시 근사). Export 는 풀해상도라 각인이 선명하다.

## 사용자 조절 / 고정 파라미터

**사용자 조절(이미지별 저장, 더블클릭 리셋):**
- **Style** — 폰트 방식 9종(7-seg/14-seg × Regular/Bold × 정체/이탤릭, + Dot-matrix).
- **Stamp size** — 숫자 높이/짧은 변 비율(1.2–5.0%, 기본 3.2%).
- **Margin** — 코너 안쪽 여백/짧은 변 비율(0–10%, 기본 5%).
- **날짜 텍스트** — 기본은 EXIF 촬영일(`'YY MM DD`), 직접 편집 가능.
- **On/Off** — `C` 키 / 체크박스.

**물리 재현을 위해 고정(사용자 노출 안 함):**
- **밝기** `STAMP_BRIGHTNESS = 0.85`, 합성 강도 `STAMP_STRENGTH = 0.92`.
- **합성 혼합** `SCREEN_MIX = 0.7`(screen 70% + source-over 30%).
- **그레인** `STAMP_GRAIN_K = 0.24`(사진 `grainAmt` 에 연동 — 독립 노출 안 함).
- **코어 선명도** `CORE_BLUR_FRAC = 0.010`, **할레이션** 글로우 계수/색.

> 조절값을 늘리기보다, "실제 필름이라면 이 값은 사진(에멀전)과 함께 결정된다"는 원칙에 따라
> 그레인은 사진에 연동하고 광학적 성격(밝기·번짐·색)은 고정했다.

## 요약

날짜 스탬프는 "텍스트 오버레이"가 아니라 **필름 에멀전에 LED 빛이 각인되는 물리 과정의 재현**이다:
빛을 더하는 **가산(screen)** 합성으로 어두운 곳엔 선명하고 밝은 곳엔 씻겨 사라지며, **사진과
같은 필름 그레인**을 타고, 강한 빛의 **할레이션**으로 적색 번짐을 남기고, **센서 프레임 기준**
코너에 방향을 반영해 놓이며, **현상된 최종 프레임**에 크리스프하게 존재한다 — 그리고 프리뷰와
export 가 같은 수식으로 이 과정을 재현한다.

## 프리뷰와 export 의 합성 차이 (원리적 한계)

export 는 `screen 70% + source-over 30%`(`SCREEN_MIX`)로 합성하고, 프리뷰는 QML `Image`
오버레이의 순수 source-over 다. 차이를 배경(bg)에 대해 정리하면 정확히 이렇게 분해된다
(실측 검증 오차 0.00003코드):

```
차이 = SCREEN_MIX × bg × a × (1 − col)        a=알파, col=각인색
```

각인 화소 최대(8bit 코드): bg 0.02 → **2** / 0.5 → **58** / 0.9 → **105**.
어두운 배경에선 사실상 같고 밝은 배경에서 벌어진다. 글로우를 키우면 커진다
(bg 0.6: 글로우 0 → 13, 2 → 73). 각인색이 중성이면 `1 − col = 0` 이라 **정확히 0**
(앰버 105 → 웜화이트 32 → 백색 0).

### export 를 그대로 두고 프리뷰만 맞출 수 없는 이유 (증명)

export 도 bg 에 대해 1차식이라 source-over 처럼 쓸 수 있다:

```
export = bg·(1 − A_c) + S_c ,   A_c = a·[(1−M) + M·col_c] ,   S_c = col_c·a
```

⚠️**실효 알파 `A_c` 가 채널별**인데 GPU 알파 블렌딩의 알파는 픽셀당 하나다. 게다가
premultiplied 유효성이 `A ≥ max_c S_c = a·col_max` 를 요구하고,
`a·col_max ≥ a·[(1−M) + M·col_max] ⟺ col_max ≥ 1` 인데 **스프라이트는 피크 정규화되어
모든 화소에서 `col_max = 1`** 이다(핫 휴 유지용). 따라서 하한이 `a` 와 같아져
**알파는 현재 값으로 고정**된다 — 각인 화소 100%에서 선택의 자유가 0임을 실측했고,
후보 6가지(채널평균/휘도가중/중간값/최대채널/유효성하한)의 최악 오차가 전부 116.3코드로
동일했다. **즉 현재 프리뷰가 단일 알파로 가능한 최선이다**(bg=0 에서 정확, 나머지는 강제).
`ShaderEffect` 를 써도 출력이 같은 알파 블렌딩을 거치므로 결론은 같다.

### 그래서 남은 선택지와 각각의 대가

| 방법 | 최악 오차 | 대가 |
|---|---|---|
| 현행 유지 | 116 | 없음(export 가 정확) — **채택** |
| 배경을 b0=0.5 로 가정해 프리뷰 보정 | 58 | 지금 정확한 어두운 배경에 58코드 오차가 생긴다 |
| `SCREEN_MIX` 0.7 → 0.35 | 52 | **export 룩이 변한다**(기존 산출물과 불일치) |
| 배경을 읽어 셰이더로 합성 | 0 | **두 번 시도해 두 번 철회**(아래) |

⚠️`shaders/stamp.frag` 배선은 **재시도 금지**. 1차=canvasHolder 전체 재캡처, 2차=스탬프
사각형만 `sourceRect` 캡처 + bgMap 항등 + ClampToEdge + 형제 배치 + 줌 시 캡처 해상도 상향까지
갖췄으나 **스탬프 영역의 영상이 밀리는** 증상이 재발했다(사용자 확인). 수식은 무죄다 —
numpy 재현으로 전 배경에서 export 와 0.000코드 일치를 확인했다. 원인은 **라이브 재캡처를
프리뷰 트리에 끼우는 구조**이고(`canvasHolder` 가 `layer.enabled` + 줌 시 `layer.textureSize`
를 바꿔 아이템 좌표와 텍스처 좌표가 어긋난다), 재검토하려면 재캡처가 없는 다른 구조를
먼저 설계할 것.

**사용자 안내**: 색 스와치 라벨 툴팁 + README 에 "밝은 배경에서 채도 높은 각인은 화면보다
흐리게 저장되고, 중성 백색은 정확히 일치한다"를 적어 두었다.

## CLAUDE.md 에서 옮긴 주의사항

- ⚠️기본 앰버(`#FF8A29`)는 **리터럴 3색을 그대로** 돌려주는 분기가 있다 — hex 8bit + HSV 왕복이 0.002(8bit 0.5코드) 차이를 남겼다.
- ⚠️영역 상쇄(`bleed_px`)는 **실제 정수 pad 의 차이**여야 한다 — 연속값(`th*1.6*(spread-1)`)으로 빼면 반올림 잔차 ±0.5px 가 영역 값에 따라 뒤집혀 **드래그 중 1px 진동**이 된다(사용자 보고). 정수 차이면 `pad - bleed == pad(기본)` 이라 글자 위치가 영역과 정확히 무관해진다(실측 0px).

  **사이드카 > 내 기본값 > 공장 기본값**이고, 어느 값으로 되돌리는지가 경로마다 다르다:
  **내 기본값을 쓰는 곳은 '사이드카 없는 새 사진의 로드 경로' 하나뿐이다**(`resetAllEdits()`
  인자 없이) — 연속 작업에서 폰트·위치를 매번 다시 잡지 않게 하는 이 기능의 목적 그 자체다.
  **Reset 버튼(`resetAllEdits(true)`)·슬라이더 더블클릭·`applyEdits` 의 `_ev` 폴백은 셋 다
  공장 기본값**이다. ⚠️①더블클릭을 내 기본값으로 두면 릴리즈마다 그 값이 기억되므로
  '기본값 == 현재값'이 되어 **더블클릭이 무동작**이 된다(사용자 보고로 고침) ②`_ev` 폴백을
  내 기본값으로 두면 스탬프 키가 없던 시절의 **옛 사이드카를 열 때 없던 각인이 갑자기 켜진다**
  ③**Reset 버튼도 같은 이유로 공장값이다** — 예전엔 내 기본값이었는데, 슬라이더를 놓을 때마다
  내 기본값이 갱신되므로 **방금 만진 값이 그대로 돌아와 Reset 이 무동작으로 보였다**(사용자
  보고: "reset 시 최근 값을 기준으로 적용되네?"). ⚠️단 `dateStamp`(켜짐 여부)는 Reset 에서도
  내 기본값을 따른다 — 각인을 통째로 없애는 것은 보고된 문제가 아니고, 새 사진을 열었을 때와
  켜짐 상태가 달라지면 더 혼란스럽다. ⚠️더블클릭 리셋은
  기억하지 않는다(공장값을 잠깐 본 것이 내 기본값을 덮으면 다음 사진부터 설정이 사라진 것처럼
  보인다). ⚠️기억은 **사용자 조작에서만** 호출한다(`win._applying` 가드) — 로드/리셋의 프로그램
  대입까지 저장하면 사이드카 있는 사진을 열기만 해도 내 기본값이 그 사진 값으로 덮인다.
- **스탬프 폰트는 번들 12종 + 사용자 추가**(`%LOCALAPPDATA%/FilmRawstery/fonts/`, 키
  `user:<파일명>`). 원하는 폰트가 없을 때를 위한 요청이었고, `Add font…` 대화상자가 윈도우
  폰트 폴더에서 열리므로 '윈도우 폰트 가져오기'와 '내 폰트 추가'를 UI 하나로 덮는다.
  고른 파일은 **복사**한다(원본이 옮겨지거나 지워져도 사이드카가 열려야 한다).
  ⚠️**삭제 전 `QFontDatabase.removeApplicationFont` 필수** — Windows 는 `addApplicationFont`
  한 파일을 잠그므로, 그 폰트를 한 번이라도 쓴 세션에서 곧바로 unlink 하면
  `PermissionError [WinError 32]` 로 **조용히 실패**한다(export 의 `os.replace` 폴백과 같은
  계열의 함정 — 실측으로 걸렸다). 그래서 삭제는 `date_stamp.remove_user_font` 한 곳에만 둔다.
  ⚠️폰트 파일이 없으면 **기본 데이트백 폰트로 폴백**한다(monospace 로 떨어지면 각인이 전혀
  다른 모습이 된다) + QML 이 `stampFontMissing` 으로 알린다 — 남의 사용자 폰트로 만든
  사이드카/레시피를 다른 기계에서 여는 것은 정상 흐름이다.
  ⚠️경로는 항상 **basename 만** 이어붙인다(`user:../../x` 가 폴더 밖을 가리키지 않게).
  ⚠️표시명과 키는 `Controller.stampFonts` **한 곳**에서 만든다 — QML 에 라벨 배열과 키 배열을
  따로 두면 순서가 어긋나 다른 폰트가 저장된다(예전 하드코딩 방식의 위험).
  ⚠️'내 기본값' 검증기도 `user:` 키를 받아야 한다(안 받으면 추가한 폰트를 기본값으로 기억 못 함).
- ⚠️**스탬프 파라미터를 늘리면 '보내는 쪽'도 함께 볼 것**: QML `editParams()`(사이드카·레시피)
  **와 export 파라미터 dict 는 별개**다. 읽는 쪽만 고쳤다가 export dict 에 키가 없어
  **내보낸 파일에만 새 룩이 빠지는** 버그가 있었다(코드 검토에서 걸렸다). 같은 실수로
  `editParams()` 에 키가 중복되기도 했다 — QML JS 는 비엄격이라 조용히 last-wins 로 넘어간다.
- ⚠️**스탬프 파라미터를 늘리면 호출부 3곳을 함께 볼 것**: `pipeline.render_full`(CPU export) ·
  `main._finish_gpu_export`(GPU export) · `main._update_stamp_layer`(프리뷰). 색/글로우/영역을
  추가할 때 **CPU export 만 빠뜨려** 프리뷰·GPU 와 다른 룩으로 찍혔다(코드 검토에서 걸렸다).
  테스트가 `date_stamp.stamp_export` 를 직접 부르면 이 누락을 못 잡는다 — **export 경로를
  통과시키거나 호출부 인자 집합을 대조**해야 한다.
- ⚠️`date_stamp._glow_pad_px` 는 `render_sprite` 의 `max(6.0, text_h_px)` **하한까지 같아야**
  한다 — 안 그러면 짧은 변 500px 미만 + 최소 크기에서 상쇄가 과보정돼 글자가 2px 움직인다.
- ⚠️사용자 폰트 추가는 **Qt 등록 결과로 판정**한다(`fid >= 0 and applicationFontFamilies(fid)`).
  `font_family(style) != "monospace"` 로 보던 검사는 font_family 가 기본 폰트 폴백을 갖게
  되면서 **죽은 코드**가 됐고, 폰트가 아닌 파일이 '성공'으로 목록에 남았다(파일은 존재하니
  누락 배너도 안 뜨고 각인만 조용히 기본 폰트로 그려졌다). 거부 시 복사본도 지운다.
- ⚠️`user_fonts_dir(create=False)` — 읽기 경로(`has_font`)는 `stampChanged` 마다, 즉 슬라이더
  드래그 중 **매 프레임** 불린다. 거기서 mkdir 를 돌리면 프레임마다 디스크를 건드리고
  사용자가 폴더를 지워도 즉시 되살아난다. 생성은 `add_user_font` 에서만.
- ⚠️'내 기본값'의 `stampStyle` 이 **없는 사용자 폰트**를 가리키면 읽는 시점에 기본 폰트로
  되돌린다 — 안 그러면 그 폰트를 참조하는 사진이 없는데도 **새 사진마다 누락 배너**가 뜬다.
- ⚠️`stampColor` 는 `setStampColor` 가 **소문자 `#rrggbb` 로 정규화**한다. 같은 색이 다른
  문자열(`#FF8A29` vs `#ff8a29`)로 `editParams()` 에 실리면 **레시피 룩 지문이 갈려** 배지가
  켜지지 않는다. 기본값 상수·QML 폴백도 같은 표기로 둔다.
- **스탬프 슬롯 4형제(`setStampText`/`Font`/`Size`/`GrainSrc`)는 전부 동일값 조기반환 가드를
  가진다** — `_update_stamp_layer` 가 GUI 스레드에서 스프라이트를 동기 재렌더하기 때문.
