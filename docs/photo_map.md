# Photo map — 폴더의 좌표를 지도 위 썸네일로 보기 (탐색기 🗺) 🇰🇷

## 왜 만들었나

위치 기능이 **한 장에 좌표를 붙이는 편집기**뿐이었다(`docs/geotagging.md`). 붙여 놓은 좌표를
**폴더 단위로 되짚어 볼 방법이 없었다** — 어느 사진이 어디서 찍혔는지, 이 폴더에서 좌표가 붙은
사진이 몇 장인지 알 수 없다.

`Photo tags`(`H`)가 "폴더의 캡션을 한 화면에서 둘러본다"를 담당하는 자리에, **"폴더의 좌표를
한 화면에서 둘러본다"** 를 놓았다.

## ★현재 상태 — 개인용(숨김)

`.env` 의 **`PHOTO_MAP=1`** 로만 켜진다(Wallpaper 패널과 같은 기계 — `main.FEATURE_FLAGS`).
릴리즈 빌드는 `.env` 를 번들하지 않으므로 🗺 버튼과 오버레이가 **전부 자동으로 숨는다.**

**기능이 미완이라서가 아니라 지도 타일이 HiDPI 에서 흐려서다.**

| 측정 | 값 |
|---|---|
| 개발 화면 | 논리 1536×960 / 물리 3840×2400 → **DPR 2.5**(Windows 250%) |
| OSM 표준 타일 | `…/13/6985/3171.png` → 200, **256×256**, 34KB |
| 레티나 타일 | `…@2x.png` → **HTTP 400** (osm.org 표준 레이어엔 없음) |

256px 타일이 논리 256px 자리에 그려지면 물리 **640px** 을 채운다 = 2.5배 확대. OSM **데이터**는
벡터라 한계가 없고, 흐린 것은 **osm.org 표준 래스터 레이어에 HiDPI 판이 없다**는 사실이다.
⚠️Location 패널 지도(`Ctrl+6`)도 원래 같았다 — 260px 상자에서 안 보였을 뿐이다.

### ★제공자 교체는 "`tileHost` 한 줄"이 아니다

플러그인 DLL 에서 뽑은 URL 템플릿:

```
'%z/%x/%y.png'                                    <- 커스텀 제공자 템플릿(고정)
'http://a.tile.thunderforest.com/landscape/%z/%x/%y.png'   <- 하드코딩 폴백들
'http://maps-redirect.qt.io/osm/5.8/'
```

`osm.mapping.custom.host` 로 만들어지는 URL 은 **언제나 `<host>%z/%x/%y.png`** 다 —
**쿼리스트링도 `@2x` 도 붙일 수 없다.** 그런데 레티나를 주는 제공자는 전부 키를 쿼리로 받는다
(Thunderforest `?apikey=` · MapTiler `?key=` · Stadia `?api_key=`, 모두 `…/{z}/{x}/{y}@2x.png`).
`osm.mapping.highdpi_tiles` 파라미터는 있지만 DLL 에 `@2x` 문자열이 **0개**다 — 그 플래그는
**제공자 저장소(`maps-redirect.qt.io`)가 주는 hi-dpi URL** 을 고르는 스위치일 뿐이고, 그 저장소는
"API Key Required" 워터마크 때문에 우리가 일부러 꺼 뒀다.

남은 우회로는 둘, 둘 다 작은 일이 아니다:

1. **제공자 저장소를 우리 것으로** — `osm.mapping.providersrepository.address` 를 우리가 통제하는
   JSON 으로 돌리면 `UrlTemplate` 을 통째로 지정할 수 있다(키·`@2x` 자유). Qt 가 `<주소>/<스타일>`
   을 네트워크로 받아가는 구조라 `file://` 이 먹는지 **미검증**이고, 안 되면 로컬 서버가 필요하다.
2. **로컬 리버스 프록시** — 앱 안 127.0.0.1 서버가 `/{z}/{x}/{y}.png` 를 업스트림 `@2x`+키로 중계.
   확실하지만 서버 수명관리·오류처리가 새로 생긴다.

### 배포본에 키를 넣을 수 없는 이유

- QML/바이너리에 박힌 키는 **추출 가능**하고, 데스크톱 앱은 referrer 가 없어 **도메인 제한 불가**.
- 한 계정 할당량을 **전 사용자가 공유**한다. 실측 뷰포트 ~28장 기준 한 세션 40~90장이면
  Thunderforest 150k/월 ≈ **월 2,000~3,700 세션** — 수백 명 규모에서 소진되고, 소진되면 예전
  사용자가 겪은 그 **워터마크가 그대로 돌아온다.**
- 무료 티어 약관(2026-09 확인): **Thunderforest** Hobby 150,000 타일/월·상업 이용 **허용**(대량
  선다운로드 금지) / **MapTiler** Free API 100k+맵세션 5k/월·상업 **불가**·MapTiler 로고 의무 /
  **Stadia** Free 200,000 크레딧/월·상업 **불가**. 셋 다 가입 필요, 카드 불필요, 키 즉시 발급.

### 재개 조건 — ★측정부터

1. **먼저 잰다**: 저장소 대체(또는 로컬 프록시)로 `@2x` 512px 타일을 물렸을 때 **실제로 선명해지는가**
   (`highdpi_tiles` 와의 조합 포함). 512px 이미지를 256px 타일 슬롯에 주면 Qt 가 되레 축소할 수 있다 —
   **여기서 안 선명해지면 나머지는 전부 무의미하므로 그대로 종료한다.**
2. 선명해지면 키를 `prefs.json`(app_dirs) 에서 읽고 **없으면 지금의 OSM 으로 폴백**하도록 배선한다.
   배포본은 지금과 동일하게 유지되고 개인 PC 에서만 본인 키로 선명해진다. 그 뒤 플래그를 뗀다.


`docs/geotagging.md` 의 "위치는 룩이 아니다"에 한 줄을 더한 것이다: **이 기능은 읽기 전용이다.**

- 셰이더 uniform **0개** · `_PRESET_KEYS`/`LOOK_DEFAULTS`/`editParams()`/export dict **무변경**
  → CLAUDE.md 의 ★렌더 경로 4중 계약에 **들어가지 않는다**.
- 좌표를 **붙이는** 일은 Location 패널(`Ctrl+6`)이 계속 단독 담당한다. 지도에서 일괄 적용까지
  하면 "클릭은 저장이 아니다" 초안 규율을 두 곳에 구현해야 하고, 기능이 두 곳에 갈라진다.
- 역지오코딩(좌표 → 지명)은 여전히 **안 한다**(그 문서의 기각 유지).

## 실측이 설계를 결정했다 (`C:\Pic\x100v\132_FUJI`)

| 측정 | 값 | 설계에 준 영향 |
|---|---|---|
| 폴더 구성 | **420 RAF + 420 짝 JPG**, 사이드카는 RAF 쪽 420개 | ★아래 '짝 JPEG' 항 |
| 좌표가 붙은 컷 | **420 / 420 (100%)** | 커버리지를 헤더에 보여줄 가치가 있다 |
| **서로 다른 좌표** | **4개** — 162 / 115 / 81 / 62장 | ★핀 420개가 아니라 **스택 마커 4개**가 진짜 그림이다 |
| 사이드카 420개 읽기 | cold **1.85s** / warm 119ms | 메인 스레드 금지 → 백그라운드 워커 |
| `exif_info.read_gps` | **1.2ms/장** | 사이드카 없는 파일 폴백은 워커에서 감당 가능 |
| 워커 전체(420컷) | **143ms** (warm) | 오버레이를 열고 바로 채워진다 |
| 서울 두 좌표 간 거리 | 565m (126.8613 ↔ 126.8677) | 폴더 전체(서울↔강원 130km)에 맞춘 **첫 화면에서 4px 안에 겹친다** → 줌별 병합이 첫 프레임부터 필요 |

★**좌표가 일괄 적용되는 것이 정상 사용 패턴이다**(`Apply to N checked` / GPX). "한 좌표에 수십~수백
장"이 예외가 아니라 기본값이므로, 마커 설계의 출발점이 **스택**이어야 한다. 이 사실을 모르고
"핀을 많이 찍는" 설계로 갔다면 첫 폴더에서 무너졌다.

## 좌표 우선순위 규칙은 함수 하나에만 있다

`main._gps_for_file(path, edits)` — **`Controller._load`(사진을 열 때)와 `_map_scan_worker`
(폴더를 훑을 때)가 둘 다 이것을 부른다.** 규칙을 두 곳에 복사하면 반드시 갈라지고, 그 증상은
**지도가 패널과 다른 좌표를 보여주는 것**이다.

⚠️**사이드카에 `gpsLat` 키가 있으면(값이 `null` 이어도) 그것이 답이다.** 키를 빼는 것과 `null` 은
다른 뜻이다 — `null` = "사용자가 일부러 지웠다"이므로 EXIF 로 폴백하면 지운 위치가 되살아난다.
검증에 이 케이스가 따로 들어 있다.

## 짝 JPEG 을 세지 않는다

카메라 RAW+JPEG 동시기록은 **한 컷**이고 사이드카는 RAW 쪽에만 붙는다. 폴더 전체를 세면 실측
폴더가 **"840장 중 420장 위치"** 로 읽히는데 사실은 **420컷 전부 위치가 있다** — 커버리지가
거짓이 된다. 그래서 `scanFolderGps` 가 `paired` 항목을 제외한다(탐색기도 기본으로 접는 항목이라
눈에 보이는 것과도 이쪽이 맞는다).

⚠️**배치 캡션 인덱서('항상 폴더 전체')와 규칙이 다르다.** 그쪽은 캡션을 **생성**하므로 빠짐이
손해지만, 여기는 **세는 일**이라 중복이 손해다. 규칙이 다른 것이 의도다.

## 그룹핑 — 두 단계

**① 파이썬: 정확히 같은 좌표** (`Controller._regroup_map_points`)
소수점 6자리(≈0.1m, `exif_info.format_gps` 와 같은 정밀도) 키로 묶는다. 일괄 적용된 좌표는
어차피 비트 동일하다. `count` 내림순 정렬 — 큰 스택이 위에 그려지고 아래 병합에서 대표로 살아남는다.

★⚠️**지금 열린 사진은 디스크 값을 덮어쓴다.** `setGps` 는 메모리만 바꾸고 사이드카는 QML 의
`saveEdits` 가 나중에 쓴다 — 그냥 재스캔하면 **옛 값**을 읽는다. 그래서 `gpsChanged` 에서는
디스크를 다시 읽지 않고 `_regroup_map_points()` 만 다시 돌린다(지도가 열린 채 `Ctrl+Z` 를
눌러도 맞는다). 그룹핑을 워커가 아니라 **메인 스레드**에 둔 이유가 이것이다.

**대표 썸네일** = 그룹 안 **좋아요된 첫 사진**, 없으면 파일명 첫 사진(`self._likes` 재사용,
새 I/O 0). 장소를 대표하는 그림이 내가 고른 한 장이면 지도가 훨씬 읽힌다.

**② QML: 줌별 화면좌표 병합** (`FolderMap.mergeForZoom`)
`map.fromCoordinate(c, false)` 로 화면 픽셀을 얻어 **84px** 안의 그룹을 그리디로 합친다
(무게중심=사진 수 가중, 대표=가장 큰 자식). 줌을 올리면 저절로 갈라진다.

- `clipToViewPort=false` 로 부른다 — 화면 밖 점도 좌표를 받아야 병합이 일관된다.
- ⚠️경도차 > 180도(날짜변경선)면 묶지 않는다 — `gpx.py` 와 같은 가드.
- 표시 상한 **60마커**(count 내림순이라 잘려도 큰 장소가 보인다), 재계산은 **120ms 코얼레싱**
  (매 프레임 다시 묶으면 마커가 춤춘다).
- 병합으로 선택이 사라지면 같은 사진을 담은 클러스터로 옮겨 붙인다(선택 유지).

## 클릭 판정 — `MapQuickItem` 안의 `MouseArea` 를 쓰지 않는다

지도 아이템은 소스를 **텍스처로 굽는** 경로가 있어(같은 이유로 `Canvas` 를 `sourceItem` 에 못
쓴다 — `LocationMap.qml` 주석) 입력이 닿는지가 상황에 달려 있다. 여기서는 병합 때문에 이미
`map.fromCoordinate` 를 쓰고 있으므로 **같은 변환으로 직접 히트테스트**한다(`FolderMap.hitTest`) —
확실하고 짧고, 마커가 ≤60개라 비용이 없다. 겹치면 **중심에 가장 가까운** 마커가 이긴다.

⚠️`MapView` 는 드래그/휠/핀치를 이미 쓰지만 **탭에는 기본 동작이 없다** — `TapHandler` 와 충돌 없음.

## 함정 기록

- ★⚠️**`MapItemView` 를 `MapView` 의 자식으로 선언하면 안 보인다.** `MapView` 는 `Map` 을 감싼
  평범한 `Item` 이라 지도의 `mapItems` 에 등록되지 않는다(핀에서 이미 겪었다).
  `map.addMapItemView(markerView)` 로 등록한다.
- ★⚠️**`ToolTip` 첨부 프로퍼티는 `import QtQuick.Controls` 가 있어야 붙는다.** `.Basic as B` 만
  두고 `ToolTip.visible` 을 쓰면 `Non-existent attached object` 로 **컴포넌트가 통째로 안 뜨고**,
  그러면 `Main.qml` 이 `Type PhotoMapOverlay unavailable` 로 **엔진 로드에 실패해 앱이 안 뜬다.**
  구현 중 실제로 났다.
- ⚠️`win.thumbPx()` 를 반드시 거친다 — 요청은 논리 픽셀이라 Qt 가 DPR 을 곱하고, 160 을 넘으면
  **0.6ms → 43.5ms(72배)** 경로로 넘어간다(CLAUDE.md 썸네일 항). 마커 72 / 스트립 96.
- ⚠️'빈 곳 클릭 = 닫기' MouseArea 를 **지도 액자 위에 깔면 안 된다** — 드래그를 먹는다.
  맨 아래에 두고 액자·스트립이 그 위에서 자기 입력을 가져간다.
- ⚠️`visibleRegion` 은 아이템 크기가 0이면 아무 일도 하지 않는다 → `fitAll()` 이 크기가 없으면
  `Qt.callLater` 로 미룬다.

## 함정 기록 — 코드 리뷰에서 잡힌 것들

전부 **한 가지 뿌리**가 셋을 낳았다: 스캔 중임을 `_map_folder = ""` 로 표현한 것.

- ★⚠️**'훑는 중인 폴더'는 따로 들어야 한다**(`_map_scanning`). `_map_folder` 를 비워 두면
  같은 폴더의 **감시 재스캔**(파일 추가·사이드카 저장)이 `folder != _map_folder` 를 만족해
  '폴더가 바뀌었다'로 읽히고, **진행 중인 스캔을 죽여 지도가 "위치 없음"으로 굳는다**
  (닫았다 다시 열기 전까지). 🗺 버튼 연타가 같은 폴더를 여러 번 훑던 것도 같은 뿌리다.
- ⚠️**스캔 중에 들어온 좌표 쓰기는 `_map_pending` 에 모았다가 결과에 합친다.** 워커가 그
  파일을 이미 읽고 지나갔으면 결과는 쓰기 이전 스냅샷이라, 방금 붙인 위치가 지도에서 사라진다.
- ⚠️**열린 사진 덮어쓰기도 `_map_paths` 안에서만.** 짝 JPEG 을 열어 두면 한 컷이 두 번 세어져
  "420장 중 421장 위치" 가 나온다(스캔 대상에서 뺀 이유와 같다).
- ★⚠️**새 전체화면 오버레이는 `_keysBlocked` 에 넣는다.** 창 단위 `Shortcut{}` 은 포커스와
  무관하게 발화하므로, 안 넣으면 지도 위에서 `D`(각인 토글 + 내 기본값 갱신)·`Ctrl+Z`·`Enter`·
  `Alt+↑` 가 뒤의 사진을 바꾼다. ⚠️**여는 단축키를 없앤 뒤에도 이 항은 남겨야 한다** —
  오버레이는 그대로 뜨기 때문이다. 여는 키가 없으니 `GUARD_EXEMPT` 예외는 필요 없다
  (예외는 자기 오버레이를 닫아야 하는 `R`·`?` 둘뿐).
- ★⚠️**`onPointsChanged` 는 내용이 같아도 발화한다.** `points` 는 파이썬 `QVariantList` 라
  읽을 때마다 새 JS 배열이 되고, `folderMapChanged` 는 사진을 열 때마다 나온다(`_set_gps` →
  `_regroup_map_points`). 그대로 `fitAll()` 을 걸면 **가까운 지점을 갈라 보려고 확대해 둔 시야가
  사진 하나 열 때마다 폴더 전체로 되돌아간다.** 내용 지문이 바뀐 경우에만 선택 해제 + 시야 맞춤.
- ⚠️**스트립은 `stackPicked`(탭)가 아니라 `selected` 를 따라간다.** 지도는 줌에 따라 선택을
  다시 매핑하거나 비우는데, 탭 신호만 들으면 합쳐진 마커 12장을 고른 뒤 확대해 셋으로 갈라져도
  머리글이 계속 "12 photos here" 다.
- ★⚠️**Location 패널의 시야 이동에서 `panelActive` 가드를 빼지 말 것.** `mapLoader.active` 는
  한 번 켜지면 다시 꺼지지 않으므로, 빼면 탭을 떠난 뒤에도 사진을 넘길 때마다 **숨은 지도의
  카메라가 움직인다** — QtLocation 은 보임 여부가 아니라 카메라로 타일을 받으므로 그대로 타일
  요청이 된다(사진 200장을 넘기면 요청 200번). '탭을 열 때만 받는다' 정책 위반이다.

### 고치지 않기로 한 것 — 두 지도가 타일 캐시 폴더를 공유한다

`LocationMap` 과 `FolderMap` 이 각각 `OsmPlugin` 을 만들므로, 두 `QGeoServiceProvider` 가 같은
`controller.mapCacheDir` 을 각자 200 MiB 예산으로 쓴다. 서로의 파일을 밀어낼 수 있고 실제 디스크
사용량이 200 MiB 로 묶이지 않는다.

**그래도 나누지 않는다.** 캐시를 크게 잡은 목적이 용량이 아니라 **남의 서버를 덜 두드리는 것**
이므로(`OsmPlugin.qml`), 폴더를 나누면 같은 타일을 두 번 받게 되어 **정책 면에서 더 나쁘다.**
증상도 디스크 사용량이지 오동작이 아니다. 릴리즈에서는 Photo map 이 숨겨져 인스턴스가 하나뿐이라
실제로 겹치지도 않는다. **플래그를 떼는 날 다시 판단할 것** — 그때는 플러그인 인스턴스를 하나로
올리는 쪽(둘 다 쓰는 공유 Loader)이 정답이고, 캐시 폴더를 나누는 쪽은 아니다.

## 타일 사용량 — ★이 앱의 첫 전체화면 지도다

`docs/geotagging.md` 실측은 **274×258 패널에서 첫 표시 5장**이었다. 전체화면 액자(~1630×700)는
뷰포트당 대략 **7×4 = 28장**이고, 열고 두어 번 줌하면 40~90장이다 — 그 문서가 "활성 사용자 1인당
**월** ~50장"으로 잡은 가정을 **한 세션에** 쓴다. OSM 의 제재는 워터마크가 아니라 **UA/IP 차단**
이라 조용히 넘어가지 않는다.

들어간 완화(새 의존성 0):

1. **앱 전용 200MiB 캐시 재사용** — 재방문 +0장(실측). `OsmPlugin.qml` 이 정책을 들고 있다.
2. **첫 화면 줌 상한 16** — `fitAll()` 이 그 이상으로 당기지 않는다. 프리페치 없음.
   ⚠️**최대 줌은 19로 열어 둔다**(조이는 쪽이 아니다). 실측: 이 폴더의 두 좌표는 **90m** 떨어져
   있는데 84px 병합을 벗어나려면 줌 ≳17.2 가 필요하다 — 상한 17이면 **끝까지 확대해도 그 스택을
   쪼갤 수 없다**(헤드리스 검증에서 걸렸다: 줌 17 → 3클러스터, 줌 19 → 4클러스터). 뷰포트당
   타일 수는 줌과 무관하니(같은 화면 = 같은 타일 수) 올리는 비용도 없다.
3. **풀블리드가 아니라 액자로 인셋** — 채택된 레이아웃이 이미 그 모양이고, 면적을 ~35% 줄인다.

⚠️**위 28장은 계산값이지 실측이 아니다.** 오프스크린에서는 타일을 받지 않아 헤드리스로 못 잰다 —
GUI 로 열어 `controller.mapCacheDir` 의 파일 수 증분을 재서 이 표를 갱신할 것. 그 수치로
`docs/geotagging.md` 의 "1만명 근처에서 제공자를 옮길 준비" 시점을 다시 판단한다.

## 검증

- **스캔 수치** — ★**실제 스캔 경로**(`_pair_flags` + `_openable_exts` +
  워커 본체)를 태운다. 손으로 만든 파일 목록으로 재면 **짝 JPEG 제외 배선을 못 잡는다**(실제로
  그렇게 한 번 놓쳤다). 기대값: `photos=420 · located=420 · places=4 · counts=[162,115,81,62]`.
- 헤드리스 QML — `main.main()` 을 그대로 태우고(함수 직접 호출은 배선 누락을 못 잡는다) Qt
  **메시지 핸들러**로 경고를 수집한다(`engine.warnings` 보다 넓다). 마커 등록(`map.mapItems` > 0) ·
  줌 19에서 4개로 갈라짐 · 줌 8에서 합쳐짐 · 히트테스트 왕복 · 사진 수 합 보존까지 확인.
  ⚠️**검증 스크립트가 조기 반환에 거짓 통과하지 않도록** `main()` 의 rc 를 검사할 것 — 처음엔
  엔진이 안 섰는데 "ALL OK" 가 나왔다(이전 실행이 단일 인스턴스 락을 쥐고 있어도 같은 일이 난다).
  ⚠️**`QQmlExpression.evaluate()` 는 PySide6 에서 `(value, isUndefined)` 튜플을 돌려준다** —
  모르고 통째로 쓰면 배열 원소가 `QJSValue` 로 보여 **멀쩡한 코드를 버그로 오진한다**(실제로
  히트테스트가 빗나간 것으로 읽혔다). JS 프로브는 아예 **문자열**로 돌려받는 편이 안전하다.
