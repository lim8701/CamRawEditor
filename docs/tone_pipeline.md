### 필름 시뮬레이션 LUT

- `luts/` 의 `.cube`(sRGB, N=32)는 abpy/FujifilmCameraProfiles 출처. 12종(identity, provia,
  velvia, astia, classic_chrome, classic_neg, nostalgic_neg, pro_neg_hi, pro_neg_std, eterna,
  reala_ace, bleach_bypass). 콤보 인덱스↔키 순서는 `ui/Main.qml win.simKeys` 와 일치해야 함.
- 더 정확한 룩이 필요하면 **같은 키 이름으로 .cube 덮어쓰기**만 하면 됨(코드 변경 불필요, 크기
  자동 인식). 근사 베이크본 백업: `luts/_approx_backup/`.
- 주의: `make_luts.py` 실행 시 실제 LUT를 근사본으로 덮어쓴다.
- ★**LUT 은 '룩'이 아니라 후지 톤커브 전체를 담고 있다 — 그래서 보정 노출이 붙어 있다**
  (`pipeline.film_sim_ev`, 셰이더 uniform `simExpEV`). 실측 그레이 전달: 0.097→0.060(섀도
  크러시) · 0.226→0.248 · **0.484→0.664(중간톤 +1스톱)** · 0.871→0.970(숄더). 우리 프론트엔드는
  이미 `filmic()` 으로 scene→display 를 끝낸 뒤 LUT 을 걸므로 그냥 얹으면 **톤커브가 두 번**
  걸린다 — 필름시뮬을 켜기만 해도 중앙값이 **+0.8~1.4EV**(provia +0.9 / classic_neg +1.2~1.4)
  뜬다. 커뮤니티 피드백 "필름 시뮬레이션을 적용하니 너무 밝아진다"(X-T5)의 원인이고 X100V
  로도 재현된다. **자동노출 솔버는 무죄다**(임베드 JPEG 중앙값 편차 0.000~0.001 — 그쪽을
  다시 의심하지 말 것).
  - 보정: LUT 통과 후 중앙값이 **베이스(None) 중앙값 = 임베드 JPEG 중앙값**으로 돌아오도록
    scene-linear 노출을 solve 해 노출 지수에 더한다. 검증(X100V, 카메라가 실제 쓴 시뮬로 렌더
    → 임베드 JPEG 분포와 퍼센타일 rms): **0.14~0.17 → 0.03~0.05**(한 장은 None 의 0.054 보다
    좋은 0.037 — LUT 곡선 **모양은 맞고 앵커만 틀렸다**는 증거). export 중앙값은 시뮬 5종·강도
    50% 에서 전부 JPEG 대비 ±0.004.
  - 앵커는 **유저 편집 전 as-shot 베이스**라 이미지×시뮬 상수다(슬라이더를 만져도 안 흔들린다).
    강도(`lutStrength`)는 solve 에 포함(0 이면 보정 0). hlDesat/톤영역은 제외 — 중앙값 영향이
    사실상 0 이고(hlDesat 이 건드리는 화소 0.02%) 앵커를 슬라이더와 무관하게 유지해야 한다.
  - 프리뷰는 `main.Controller._update_sim_ev`(표본 `_proxy_small`) → uniform, export 는
    `render_full` 이 스스로 계산(표본 풀해상도 1/128) — **같은 함수·같은 앵커라 실측 차
    ≤0.005EV**. 프록시/풀해상도 표본이 다른 것은 `auto_exposure_gain` 과 같은 기존 관례다.
  - solve 는 표본 긴 변 64px(≈2.8k px) × 이분법 12회 ≈ 20ms. ⚠️강도 슬라이더는 120ms
    디바운스(`simEvTimer`), 시뮬 교체는 즉시(한 프레임이라도 보정 전 룩이 보이면 번쩍인다).
  - ⚠️`pipe`/`pipeFull` **두 ShaderEffect 모두** `simExpEV` 를 물려야 한다(프리뷰=Export).
    `comparePipe`(displaycm.frag)는 LUT·노출이 없으므로 대상이 아니다.
  - 남은 것(별건): **None 베이스는 여전히 '플랫 톤커브를 중앙값으로 JPEG 에 맞춘' 상태**라
    원리상 하이라이트가 카메라보다 뜬다(퍼센타일 p1 이 JPEG 0.05~0.10 대비 0.14~0.18 로 뜨고,
    밝은 하늘이 숄더로 밀려 채도가 무너진다 — 같은 피드백의 "색감이 많이 달라요"). 베이스
    톤커브 재설계는 룩 전체가 바뀌는 변경이라 이 수정에 포함하지 않았다.

### 하이라이트 디새추(hlDesat) — 게이트는 **센서 클립**이지 display 밝기가 아니다

near-clip 센서 클립의 색끼(불꽃 코어 청록 등)를 중성화하는 0.5 단계. 밝기 게이트를 display 값
(`smoothstep(0.95,1,mx)`)으로 두었더니 **정반대로 작동**했다 — 자동노출 게인(+0.9~2.1EV)과 filmic
숄더가 밀어 올려서 **센서 포화의 20~51% 밖에 안 되는 멀쩡한 파란 하늘**이 0.95 를 넘는다.

- 실측(X-T5 FXT50017, 하늘이 큰 사진): 발동 **14.0%** / 그 화소의 센서값 중앙 **0.51**(포화=1.0,
  p5 0.44~p95 0.58) / 진짜 색끼 부분클립 화소 중 발동 **0개**. 철탑 주변 **흰 후광**의 정체였고,
  커뮤니티 피드백 "RAW 를 열었더니 색감이 많이 다르다"의 실체다. X100V 샘플은 0.01~0.02% 라
  오래 안 드러났다.
- 수정: 게이트를 `smoothstep(0.90, 1.0, cam_max / clipLevel)` 로 교체. `cam` 은 **미스트/유저 WB/
  노출보다 앞**의 카메라네이티브 scene-linear(파일의 성질이지 슬라이더의 함수가 아니다),
  `clipLevel` = `raw_loader.clip_level(자동게인)`.
- 왜 clipLevel = 자동게인인가: 디코드는 카메라네이티브 1.0 = 센서 포화이고 거기에 게인 g 를
  곱하므로 포화 레벨이 곧 g 다. ⚠️**g > PROXY_HEADROOM(4.0) 이면 게이트를 끈다**(도달 불가능한
  값을 돌려준다) — 프록시가 L/H 를 [0,1] 로 클램프하므로 그런 사진(후지에선 흔하다: +2.4EV =
  5.4배)은 센서 H/g 이상이 한 값으로 뭉개져 **클립 여부를 구분할 수 없다**. 처음엔 `min(g, H)`
  로 상한을 뒀는데 그게 오히려 g=5.4 에서 게이트를 센서의 0.67 부터 열어 이 게이트가 고치려던
  증상을 재현했다 — 아래 §② 참조. 프리뷰·GPU export·CPU export 는 **한 값을 공유한다**
  (`params["clipLevel"]`, 요청 시점 스냅샷) — 프리뷰=Export.
- 결과(같은 표본 before/after): FXT50017 None 의 임베드 JPEG 대비 rms **0.049 → 0.011**
  (p90 0.882→0.797, JPEG 0.792), 평균 채도 0.360→0.384, 발동 14.04%→0.00%.
  X100V 2장은 **완전 무변화**(원래 발동이 0.01~0.02%), xplat 19케이스 해시 전부 동일.
- ⚠️죽은 코드가 된 것이 아니다 — clipProx 최대는 세 파일 모두 1.000 이고 실제 클립 화소
  비율과 일치한다(DSCF8035 4.6%). 다만 LibRaw `highlight_mode=Clip` 이 전채널 클립을 이미
  중성으로 만들어 두므로 대개 `cool` 게이트에서 걸러진다 — **원래 노리던 '색끼가 남은 부분
  클립'에서만** 작동한다.
- ⚠️계약 변경: `load_proxy`/`load_full` 반환이 **7-튜플**이 됐다 — 마지막은 **자동노출 게인**
  이지 clip_level 이 아니다. 호출부(`main._on_render_ready`)가 그 게인 하나에서 두 가지를
  파생한다: `raw_loader.clip_level(게인)`(게이트 기준)과 `_auto_ev = log2(게인)`(UI 의 Auto EV
  표시). ⚠️여기에 clip_level 을 넣으면 게이트는 이중 적용되고 Auto EV 는 log2(clip_level) 이
  된다. `image_loader` 는 1.0 을 돌려준다(display-referred 는 센서 클립이 없고 hlDesat=0).
- ⚠️같은 게이트가 **`adjust.frag`·`displaycm.frag`·`pipeline` 세 곳**에 있다. `displaycm.frag`
  (Compare original)는 입력이 display 라 클립 정보가 없어서 **원본 프록시를 binding 3(`rawSrc`)
  으로 따로 받는다** — QML `comparePipe` 에 `rawSrc`/`clipLevel` 을 물리는 것을 잊지 말 것.
- ⚠️테스트 스크립트에서 잴 때 **`nat` 에 자동노출 게인을 곱한 뒤** 재야 한다. 안 곱하면
  clipProx 가 항상 0 이 되어 '게이트가 죽었다'는 잘못된 결론이 나온다(실제로 한 번 그랬다).
- ★⚠️**게인 관련 수치는 반드시 `load_proxy` 경로(=렌즈 보정 포함)에서 잴 것.** `_decode_native`
  로 직접 재면 **비네팅 보정이 빠져** 자동노출 게인이 0.2~0.4EV 과대평가된다(실측 FXT50017
  +0.91 vs +1.26EV). 이 절의 수치가 한 번 그렇게 부풀려 적혀 있었고, 나중에 그대로 인용됐다.
  `verify-the-real-path` 와 같은 계열의 함정 — 함수를 직접 부르는 테스트는 앞단을 건너뛴다.

### 자동노출 — 보이게 하고, 끌 수 있게

디코드 때 **평평한 베이스 렌더의 중앙값이 임베드 JPEG 과 같아지도록** scene-linear 게인을 풀어
곱한다(`wb.auto_exposure_gain`). 실측 적용량 **+0.9~2.2EV**(후지 raw 는 하이라이트를 지키느라
낮게 노출된다 + 우리 베이스엔 S커브가 없다).

- ★**이 보정은 보이지 않았다** — Exposure 슬라이더는 0.00 인데 뒤에서 +2EV 가 걸려 있었다.
  커뮤니티 피드백이 계속 이 주위를 맴돈 이유이고("왜 내가 찍은 것보다 밝지"), 그래서
  **적용된 값을 Exposure 줄에 그대로 표시**한다(`controller.autoExposureEV`, 0 이면 숨김).
  ⚠️토글 체크박스는 **Exposure 라벨과 같은 줄 오른쪽 빈 공간**에 둔다(`padding: 0` + 18px).
  슬라이더 밑에 별도 행으로 넣었더니 Light 섹션의 행 간격이 한 칸 벌어져 리듬이 깨졌다
  (사용자 지적).
  ⚠️**체크박스는 줄의 맨 끝(오른쪽 고정)**, 값 글자는 그 왼쪽이다. 반대로 두면 켬/끔에 따라
  `Auto +0.91EV` ↔ `Auto` 로 폭이 달라져 **체크박스가 51px 좌우로 움직인다** — 연달아 껐다
  켜기가 불편하다(사용자 지적, 실측 x 1459→1510 → 고정 후 1552 유지). 늘었다 줄었다 하는 것은
  글자 쪽이어야 하고, 밀리는 폭은 `fillWidth` 인 Exposure 라벨이 흡수한다(그쪽에 elide +
  `minimumWidth: 0`).
  ⚠️네이티브 스타일 체크박스는 **오프스크린 렌더에 안 그려진다** — 눈으로 못 보므로
  `objectName` 을 붙여 **좌표로** 검증할 것(위 x/폭·라벨 truncated 는 그렇게 잰 값이다).
- **끌 수 있다**(`autoExposure`, 사진별 사이드카). 끄면 **톤 가공 없는 선형 출발점**(캡처원
  Linear Response 와 같은 자리). 실측 중앙값 0.19~0.38 로 1~2스톱 어둡게 열리므로 **기본은 켬**
  이고 알고 쓰는 옵션이다.
  - ★**끄기는 재디코드가 아니라 노출 오프셋이다.** 디코드는 **항상** 게인을 적용하고, 끄면
    셰이더 uniform `autoExpEV`(= −log2(게인))를 노출 지수에 더한다. 곱셈이라 수학적으로 같고
    **토글이 24ms 에 반응**한다. 처음엔 `lensCorrection` 처럼 재디코드로 만들었다가 2~4초가
    걸려 바꿨다(사용자 지적).
  - ⚠️유일한 대가: 프록시 헤드룸 클램프(H=4)로 **센서 H/g 이상이 뭉갠다**. 실측 손실
    **0.000~0.388%**(게인 +2EV 초과 파일만, 그것도 near-clip 화소). CPU export 는 float 라
    클램프가 없어 **수학적으로 정확**하다(auto off 중앙값이 재디코드판과 동일: 0.377/0.381).
  - ⚠️`film_sim_ev` 는 **오프셋이 걸린 베이스**에서 다시 풀어야 한다 — 끄면 베이스가 어두워져
    LUT 이 얹히는 자리가 달라진다(실측 −1.065 → −0.777EV). 토글이 24ms 인 것은 이 재계산 값이다.
  - 부수 확인: 선형에서는 하이라이트 숄더(knee 0.7)가 **거의 안 걸린다**(37.1%→0.37% /
    19.9%→0.01%). 센서가 실제로 날아간 파일만 4.7% 로 남는다 → 숄더까지 따로 끌 필요 없다.
  - ⚠️"순수 raw 데이터"가 아니다 — 디모자이크·WB·카메라 매트릭스는 그대로다(빼면 화면에 못
    띄운다). 캡처원 Linear Response 도 마찬가지로 **톤 커브만** 안 건다. 답변할 때 이 구분을
    지킬 것.
- 프리셋에는 넣지 않는다(촬영 조건 보정이지 룩이 아니다 — `lensCorrection` 과 같은 이유).
- ⚠️배선은 **룩 파라미터(uniform) 쪽**이다: `adjust.frag` + `pipeline.render_full`(`params` 의
  `autoExposure` → `_auto_off`) + QML `pipe`/`pipeFull` 둘 다. GPU export 디코드는 손대지 않는다.

## 기존 사이드카에 미치는 영향 (필름시뮬 보정 도입)

보정 노출이 붙으면서 **예전에 편집한 사진이 최대 1.4스톱 어둡게 열린다** — 그때는 시뮬이
그만큼 밝게 그리고 있었고 사용자는 그 화면 기준으로 다른 슬라이더를 맞춰 두었기 때문이다.
실측 사이드카 312개 중 **290개가 필름시뮬을 쓰고 있어** 영향 범위가 넓다.

**사이드카 자동 환산은 하지 않는다** — 그레인 강도를 0.21→0.24 로 올렸을 때와 같은 판단으로,
지금 렌더가 카메라 JPEG 밝기에 맞는 쪽이고 룩 변경이 의도다.

## 2차 코드 검토에서 잡힌 두 가지 (2026-08)

**① `film_sim_ev` 는 상한 0 이어야 한다.** '베이스 중앙값 보존'이라는 앵커는 LUT 이 그 중앙값에서
**들어올릴 때만** 성립한다. 베이스가 어두워 중앙값이 LUT 의 크러시 구간(그레이 전달 교차점 ≈0.23
아래)에 앉으면, 중앙값을 지키려고 입력을 거꾸로 밀어 올린다.

| 0.012 | **+2.00EV**(탐색 경계) | p95 0.011 → **0.473** 하이라이트 폭발 |
| 0.019 | **+2.00EV** | p95 → 0.584 |
