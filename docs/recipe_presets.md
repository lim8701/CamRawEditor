# 레시피 프리셋 (`.frpreset`)

> `CLAUDE.md` 에서 분리했다(그 파일은 매 세션 컨텍스트에 통째로 올라가므로 가볍게
> 유지한다). CLAUDE.md 에는 요약과 이 문서 포인터만 남아 있다.

편집 '룩'만 저장/공유하고 **출처를 함께 기록**한다. 목적이 "레시피는 장비에 묶여 있다"를 사용자가
알게 하는 것이므로(피드백 발단), 기록만 하지 않고 **적용 시점에 배너로 보여준다**.

- **담는 키의 단일 진실원 = `main.Controller._PRESET_KEYS`** (QML 에 `presetKeys` 로 노출).
  저장 필터·로드 필터·QML 의 '기본값으로 되돌릴 키' 목록이 **반드시 이 하나**를 봐야 한다.
  ⚠️새 슬라이더를 추가하면 이 목록에 넣을지 판단할 것 — 넣지 않으면 프리셋에 안 실리고,
  검증 스크립트가 `_PRESET_KEYS + 제외 = editParams() 전체`를 대조하므로 그때 걸린다.
- **제외 이유**(각각 다름): `exposure`=WB 와 같은 **촬영 조건 보정**이지 룩이 아니다(실측:
  사이드카 245개에서 −0.81~+3.00 스톱, **71%가 기본값 아님** / WB 100% / 대비 60%. 저노출
  프레임을 +3 올려 만든 레시피를 정상 노출 사진에 적용하면 하얗게 날아간다. 밝기 성격이 있는
  룩은 whites/blacks/커브로 담는다. 옛 레시피의 `exposure` 는 `read()` 가 걸러 자동 무시 —
  마이그레이션 불필요) · `temp`/`tint`=장면 조명별 · 크롭/기하/`stampText`/`dateStamp`=사진별
  · `maskLayers`=그 사진 구도에 묶임(숫자만 실으면 `layerHasMask` 게이팅 때문에 "슬라이더는 0이
  아닌데 효과가 0"인 상태가 되어 **더 나쁘다**) · `aiNr`=수신자 기계에서 모델 다운로드·모달 유발
  · `lensCorrection`=그 렌즈/그 샷 성질 + 풀 재디코드 유발 · `lumaNR`/`colorNR`=그 사진 ISO 의존.
  ⚠️**복사/붙여넣기는 `lumaNR`/`colorNR`/`maskLayers` 를 싣는다** — 프리셋과 의도적으로 다르다.
- ⚠️**적용은 `applyPresetEdits` 의 3단 병합**이어야 한다. 프리셋 dict 를 `applyEdits` 에 그대로
  넘기면 `applySkyEdits` 가 **대상 사진의 마스크를 삭제**하고 WB·크롭·스탬프 텍스트도 초기화된다.
  병합만 하면 **이전 프리셋의 룩이 남는다** → 프리셋 소유 키를 먼저 지운 뒤 덮어쓴다.
  삭제 목록은 **정확히 `presetKeys`**(프리셋이 안 가진 키를 지우면 기본값으로 강제 — 예:
  `lensCorrection` 은 기본 true 라 조용히 켜지며 재디코드). `simIndex` 도 지워야 이전 필름시뮬이
  부활하지 않는다.
- ⚠️`applyEdits` 는 **`try/finally`** 로 감쌀 것 — 프리셋은 앱 외부에서 편집·공유되는 첫 입력이고,
  예외가 나면 `_applying` 이 영구 true 로 남아 그 세션의 자동저장·undo 가 조용히 죽는다.
- ⚠️배너는 **undo/redo(`applySnapshot`)와 사진 전환(`onEditsReady`) 두 곳에서 지운다** — 없으면
  Ctrl+Z 후에도 "남의 레시피 적용됨"이라 거짓말을 한다.
- ⚠️**초점거리는 비교하지 않는다**(줌이면 매번 오탐). 비교는 `camera`, 그리고 `lens` 는 양쪽에 다
  있을 때만. 렌즈는 대부분 빈다 — 고정렌즈 바디는 태그를 안 쓰고 `_exif_tags` 는 `details=False`
  로 MakerNote 를 파싱하지 않는다(실측 8개 파일 전부 없음).
- 파일명: 앱 내부는 `<이름>.frpreset` 로 짧게(패널 300px 라 출처를 넣으면 잘려 오히려 안 보인다),
  **공유(Export) 제안 파일명에만** 출처를 넣는다. 파일명은 항상 **내부 `name` 에서 재파생**
  (들어온 파일명을 믿으면 `../../foo` 가 경로 탈출 쓰기가 된다).
- `.frpreset` 파일 연결은 등록하지 않음 → 공유받은 파일은 **Import 로만** 들어온다.
- **목록은 1열 행 리스트**(폭 전체, 행 44px: 왼쪽 구분색 세로 줄 + 이름 + 장비 한 줄).
  ⚠️예전엔 3열 87×56 배지 그리드였다(참고 이미지 film_recipe.png 밀도). 카메라/렌즈를 손으로
  입력할 수 있게 되자 **87px 에 이름과 장비를 함께 담을 수 없었다**(9px 글자로 약 16자) —
  폭을 늘리는 것이 유일한 해법이라 행으로 바꿨다(사용자 선택). 이제 한 줄에 약 40자가 들어가
  제조사 접두 축약도 하지 않는다.
- **순서는 사용자가 드래그로 바꾼다.** ⚠️순서는 **`prefs.json` 의 `recipes.order`**(키 목록)에
  둔다 — 레시피 파일에 넣으면 **공유받은 파일이 남의 순서를 들고 온다**. 순서는 내 로컬
  취향이고 레시피의 일부가 아니다. 키는 `id`, 없으면 `file:<파일명>`(id 도입 전 파일이 실제로
  있다). 새로 만들거나 가져온 레시피는 **맨 위**(방금 만든 것이 위치로 드러난다), 목록에 없는
  것도 맨 위·이름순. 사라진 레시피의 항목은 조회 때 정리해 목록이 무한히 자라지 않게 한다.
  ⚠️**입력(마우스)은 목록 전체를 덮는 MouseArea 하나에서만 받는다.** 행마다 MouseArea 를 두고
  그 행을 `Translate` 로 끌었더니 **좌표 피드백 루프**로 위치가 요동쳤다(사용자 보고): `mouse.y`
  는 끌리는 행의 **로컬 좌표**라 행이 내려가면 로컬 y 가 줄어 dy 가 줄고 → 행이 되올라간다.
  입력은 움직이지 않는 프레임에서 받아야 한다. 행 높이가 고정이라 인덱스는 `y/스트라이드`
  나눗셈으로 나오므로 오히려 단순하다(호버 인덱스도 같은 레이어가 관리).
  ⚠️드래그는 **4px 문턱**을 넘어야 시작한다 — 넘지 않으면 클릭(적용)이다. 바깥 Flickable 이
  세로 드래그를 가로채지 않게 `preventStealing: true`(커브 에디터와 같은 이유). 끌리는 동안
  레이아웃을 건드리지 않고 `transform: Translate` 로 그 행만 띄운다(ColumnLayout 안에서 y 를
  바꾸면 레이아웃과 싸운다).
- ⚠️**배지 비교는 그 레시피가 '지정한 키 집합'에서만** 한다(`presetList` 의 `lookKeys`,
  `lookHash(edits, keys)`). `_PRESET_KEYS` 가 나중에 늘어나면(예: 스탬프 색·글로우 추가)
  **옛 레시피의 지문은 적은 키로 계산돼 있어 전체 키 지문과 영원히 달라진다** — 실제로
  "적용은 되는데 앰버가 안 켜지는" 레시피가 생겼다(사용자 보고). 레시피가 언급하지 않은 키는
  비교 대상이 아니다("이 레시피가 지정한 값들이 지금 다 적용되어 있는가"가 배지의 의미).
- **카메라/렌즈는 대화상자에서 직접 고칠 수 있다**(`savePreset`/`editPreset` 의
  `src_override`, `Controller._merge_source`). 렌즈는 EXIF 로 거의 얻을 수 없어(고정렌즈 바디는
  태그를 안 쓰고 `_exif_tags` 는 MakerNote 미파싱) 늘 비었는데, 그러면 "레시피는 장비에 묶여
  있다"는 이 기능의 목적이 반쪽이 된다. 나머지 출처(초점거리·조리개·ISO·촬영일)는 자동값을
  보존하고 두 항목만 덮어쓴다. 공백 정리 + 60자 상한(`_SRC_TEXT_MAX`).
- ⚠️**입력칸에는 라벨을 붙인다** — placeholder 는 값이 채워지면 사라져 어떤 항목인지 알 수
  없다(자동 기입되는 카메라/렌즈에서 특히 문제였다는 지적).
- ⚠️**파이썬 슬롯에 인자를 추가하면 `@Slot(...)` 선언도 같이 고칠 것.** 기본값만 추가하면
  QML 의 다인자 호출이 **조용히 실패**한다(배지가 안 켜지는 원인이었다).
- **배지 활성 = 지금 룩이 그 레시피와 같은가.** 그것뿐이다(`badgeOn`, `look_hash` 비교).
  ⚠️**'이 레시피에 기반했으나 수정됨'(흐린 앰버) 2번째 상태를 사이드카 계보로 구현했다가
  전부 제거했다 — 되살리지 말 것.** 배지가 '보이지 않는 이력'의 함수가 되면 **룩이 완전히
  같은 두 사진이 서로 다른 배지를 보인다**(레시피로 만든 쪽 vs 붙여넣기로 만든 쪽). 화면에서
  구분할 근거가 없는 차이라 설명이 불가능했다(사용자 보고: "경우에 따라 활성화가 되고 안되고의
  차이가 혼란을 준다"). 함께 사라진 것: 사이드카 `recipe` 키 · `presetRef` · 배지 우클릭
  `Forget on this photo` · 그 셋이 만든 버그 3건(붙여넣기 지문 누락, Reset 후 계보 잔존,
  "룩이 같은데 배지가 다름"). **옛 사이드카의 `recipe` 키는 읽고 버린다**(하위호환).
  레시피의 **출처(카메라·렌즈·촬영일·appVersion)는 그대로다** — 그건 레시피에 붙은 정보이고
  이 기능의 원래 목적이다. 사라진 것은 *사진→레시피* 링크뿐이다.
- ⚠️**룩 지문 갱신은 `histPush`/`histReset` 두 곳에서만** 한다(+ `applySnapshot` — undo/redo 는
  push 하지 않는 유일한 예외). 개별 경로(commit/paste/reset/apply)에 흩어 뒀더니 **붙여넣기와
  Reset 버튼에서 빠져** 룩이 레시피와 같아졌는데도 배지가 안 켜졌다(사용자 보고). 룩을 바꾸는
  경로는 예외 없이 히스토리에 스냅샷을 남기므로 그 둘이 유일한 공통 지점이다.
- **'해제' 기능은 두지 않는다** — 배지가 값의 함수이므로 지울 '선택'이 없다. 적용을 되돌리는
  것은 `Ctrl+Z`(스냅샷 복원)와 Reset all 이 담당한다.
- 레시피 파일의 안정 `id`(`uuid4().hex[:12]`)는 계보 링크용으로 넣었던 것이지만, 이름 변경·룩
  갱신에도 정체성이 유지되는 값이라 파일에는 계속 쓴다(`editPreset`/`updatePresetLook`/
  `importPreset` 이 넘긴다). 지금 배지 판정에는 쓰이지 않는다.
- 파일명: 앱 내부는 `<이름>.frpreset` 로 짧게(패널 300px 라 출처를 넣으면 잘려 오히려 안 보인다),
  **공유(Export) 제안 파일명에만** 출처를 넣는다. 파일명은 항상 **내부 `name` 에서 재파생**
  (들어온 파일명을 믿으면 `../../foo` 가 경로 탈출 쓰기가 된다).
- `.frpreset` 파일 연결은 등록하지 않음 → 공유받은 파일은 **Import 로만** 들어온다.
- **배지 활성 표시는 참조가 아니라 룩 지문(`look_hash`) 비교로 정한다.** 사이드카에 `recipe`
  키(`{id, name, file, lookHash}`)를 함께 저장해 사진을 다시 열면 계보가 복원되는데, 배지의
  '활성'을 그 참조로 판정하면 **적용 후 슬라이더를 만져도 활성으로 남아 배지가 거짓을 말한다.**
  3단계: **2=현재 룩이 그 레시피와 일치**(앰버 실선) / **1=그 레시피에 기반했으나 수정됨**(흐린
  앰버) / **0=무관**. 참조가 필요한 것은 1단계 하나뿐이다. 이 판정 하나가 세 가지 애매한
  상황(적용 후 수정 / 레시피 룩이 갱신됨 / 레시피 삭제됨)을 전부 자동으로 처리한다 —
  룩이 갱신되면 지문이 달라져 저절로 1로 내려가고, 삭제되면 그릴 배지가 없다.
- **'해제'는 별도 기능으로 두지 않는다** — 배지가 값 기준이라 지울 '선택'이 없다. 적용을
  되돌리는 것은 `Ctrl+Z`(스냅샷 복원이라 룩과 계보가 **함께** 되돌아간다)와 Reset all 이
  이미 담당한다. ⚠️`resetAllEdits` 는 **계보도 지운다** — 안 지우면 편집이 하나도 없는 사진에
  "그 레시피에 기반했으나 수정됨" 배지가 남아 배지가 거짓을 말한다(실측으로 걸렸다).
  다만 적용 후 룩을 완전히 바꿔 원형이 없어진 경우를 위해 배지 우클릭에
  **`Forget on this photo`**(계보만 지우고 룩·레시피 파일은 불변, undo 1스텝)를 둔다.
- **레시피에 안정 `id`**(`uuid4().hex[:12]`)를 두고 이름 변경·룩 갱신에도 보존한다
  (`editPreset`/`updatePresetLook`/`importPreset` 이 전부 넘긴다). ⚠️`file`/`name` 만으로 계보를
  링크하면 **이름을 바꾸는 순간 파일명도 바뀌어 링크가 끊긴다**(`editPreset` 이 이름에서 파일명을
  재파생하므로). `id` → `file` → `name` 순 폴백이라 구버전 사이드카도 계속 붙는다.
- ⚠️`recipe` 는 `_copyExclude` 에 있어 **붙여넣기로 옮겨가지 않는다** — 남의 계보를 주장하지
  않게. `_PRESET_KEYS` 에도 없어 프리셋 안에 프리셋 참조가 들어가지 않는다.
- 지문 갱신 지점 4곳: `commitEditSnapshot`(편집 커밋) · `applySnapshot`(undo/redo) ·
  `applyPresetFile`(적용) · `onEditsReady` 의 `histReset` 뒤(**사진 로드 — 재오픈 시 배지 복원의
  핵심**). 드래그 중 매 프레임 계산하지 않는다.
- 저장 위치: `%LOCALAPPDATA%/FilmRawstery/presets/` (models 와 같은 base dir — 로밍 안 되고
  언인스톨 후에도 남는다. 기능 하나 때문에 두 번째 base dir 를 만들지 않는다).

## exposure 재검토 (2026-08 / 재측정 2026-08-26) — 현행 유지, **근거는 아래가 최신**

`exposure` 를 프리셋에 넣자는 재검토가 **두 번** 있었다. 결론은 두 번 다 '넣지 않는다' 지만,
**1차 때 적어둔 근거 중 네 가지가 틀렸다.** 그대로 두면 다음 사람이 같은 자리에서 또 막히므로
(실제로 2차에서 그렇게 됐다) 여기서 정정한다.

### 재측정 (사이드카 314개, `C:\Pic` 전체)


### 틀린 근거 (인용 금지)

1. ❌ *"σ 0.50 이 평균 0.25 의 두 배다 → 룩이 아니다"* — **비교 대상이 잘못됐다.** σ 는 사진별
   흩어짐이고, 체계적 성분의 유무를 판정할 값은 **평균의 표준오차**(0.0276)다. **+0.25 스톱은
   0 에서 9.2σ** 다. "개인차가 ±10cm 니 평균 170cm 는 의미 없다"와 같은 오류.
2. ❌ *"폴더 평균들의 σ 0.324 → 뭉치지 않는다"* — 같은 숫자를 검정하면 **F=32.07**, 세션 간
   차이는 압도적으로 유의하다(ICC 0.33).
3. ❌ *"실측은 전부 양수다"* — **평균 −0.386 인 세션이 있다**(n=38). 부호가 뒤집히는 세션이
   존재하므로 '한쪽으로 쏠린 보정'이라는 해석도 성립하지 않는다.
4. ❌ *"저노출 프레임을 +3 올려 만든 레시피"* — **그런 레시피는 없다.** 최댓값 +2.61,
   1스톱 초과가 7.0%, 43.6% 는 ±0.25 안이다.
5. ❌ *"라이트룸은 자동노출이 없어 exposure 를 싣는 것"* — 라이트룸은 New Develop Preset
   대화상자의 **개별 체크박스**로 싣는다(`crs:Exposure2012`). 정규화되지 않은 값인데도
   선택지를 준다. 우리 값은 자동노출이 카메라 JPEG 밝기에 못박아 둔 기준 위의 값이라
   (**99.7% auto ON**) **오히려 전달이 더 잘 되는 값**이다 — 이 논거는 방향이 반대다.

### 유지하는 이유 (이것만 인용할 것)

- **세션 안의 sd 가 0.4299 다.** 레시피를 만든 그 한 장의 값에는 룩(+0.25~0.37)과 그 사진
  고유분(±0.43)이 **섞여** 있고, **사이드카만으로는 분리할 수 없다** — 의도는 데이터에 남지
  않는다. 값을 그대로 실으면 편향(−0.25)은 사라지지만 원본 사진의 흩어짐을 물려받아 RMS 로는
  현행(항상 0)보다 나빠질 수 있다.
- 분리하려면 ①저장 시점에 사용자가 값을 확인·수정하는 UI 또는 ②밝기 슬라이더 이원화가
  필요한데, **둘 다 오해를 부른다.** 설계 검토 중 저장 다이얼로그 시안의 `Look brightness
  +0.42EV` 라벨이 *"자동으로 0.42 보정됨"* 으로 읽힌 실례가 있었다(앱 저자가 그렇게 읽었다).
  얻는 값 ≈0.25 스톱에 비해 비싸다.
- ★**LUT 이 들고 있는 밝기는 이 문제와 별개다.** 사용자가 추가한 LUT(`user:`)은 `simExpEV`
  보정을 **받지 않으므로** 밝기가 LUT 파일에 남고, `simKey` 는 이미 `_PRESET_KEYS` 에 있으니
  **레시피로 그대로 전달된다**(`main.Controller._update_sim_ev` / `pipeline.render_full` 의
  게이트). "밝은 룩이 레시피에 안 담긴다"던 구멍은 exposure 가 아니라 여기서 막혔다.

⚠️**다시 재지 말 것** — 위 수치가 최신 실측이다. 재측정 스니펫은 사이드카를 순회해
`exposure`/`autoExposure`/폴더로 그룹만 하면 되므로 필요하면 즉시 재현된다.

### `lumaNR`/`colorNR` (변동 없음)

제외 이유는 애초에 버그와 무관하다(적정량이 그 사진 ISO·노이즈에 묶임). 실측 비기본값 15.4%.
**복사/붙여넣기는 exposure·NR 을 이미 싣는다**(`_copyExclude` 에 없음) — 같은 촬영 안에서
옮기는 길은 이미 있고, 프리셋은 다른 촬영·다른 카메라로 건너가는 통로라 안 싣는다.
